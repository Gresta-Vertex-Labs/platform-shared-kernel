## Open Work

### SK.01.CoreObservabilityFixes — Core observability and exception defects `○`

**Work order:** WO-087 / P-584 · **Depends on:** SK.01.ObservabilityHelpers (P-580: `IHasError` is satisfied by `SharedKernelException`)

Fixes the Phase 1 defects found in Foundation (audit Part 1, items 5, 9 and the exception-text sweep). (1) `SharedKernel.FeatureManagement` copies `ex.Message` into the OpenFeature evaluation message (`TypedValueConverter.TryConvert`, `FeatureFlag.EvaluateObjectAsync`) and into the startup `FeatureFlagValidationException` lines (`CheckVariant`); the converter's own `JsonException` texts also quote the configuration value (`'{value}' is not true or false.`, `'{text}' is not a number.`). All of it is replaced by a closed vocabulary of fixed reasons, so no exception text and no configuration value reaches a message (rule 27). (2) `CommitOutcomeUnknownException`, `TransactionRolledBackException` (both `SharedKernel.Execution`) and `FeatureFlagValidationException` carry no `Error`, so the three edge mappers (`SharedKernelExceptionHandler`, `GrpcExceptionInterceptor`, `HubExceptionMappingFilter` each switch on `SharedKernelException`) map them to 500 and lose the failure; each gets an `Error` and derives `SharedKernelException`. Sweep result for "other exception text in logs or results": the runtime hits are only the FeatureManagement ones above; `ResultTry` (fixed message), the Key Vault readiness report (status code or exception type name only) and the only `[LoggerMessage]` in Foundation (passes the exception, no `.Message`) are clean; the four startup-time exceptions that embed an inner `ex.Message` in `SharedKernel.Localization` (`JsonTranslationReader.cs:26,83`, `MessageDefinition.cs:26,68`) are message-style (E3) findings that never reach a client or a log as text, and are handled in `SK.01.CoreConformance`. No `throw ex;`/`throw exception;` exists in Foundation (grep), so the stack-trace bullet is proven by tests that pin the new wrappers keep the original exception as the same `InnerException` instance. **Stored/wire formats:** none touched. Three new error codes are new wire strings, pinned literally.

**Blast radius (consuming domains).** `Execution` gains a `ProjectReference` to `Core` (D-01), so every package that references `Execution` (about 24, in 02, 03, 05, 06, 07, 08, 09, 10, 11, 13, 14, 15, 17, 18, 19, 20 and 16) inherits `Core` transitively and its `.nuspec` gains a dependency: additive, no cycle (`Core` references `Primitives` only). `TransactionRolledBackException` stops being an `InvalidOperationException` (breaking for a `catch (InvalidOperationException)`; the only in-repo throwers are `06` (`UnitOfWorkCoordinator`) and `FakeUnitOfWork` in `06`'s `.Testing`, both use ctors this phase keeps). The three exceptions' codes and `ErrorType`s become what `14`/`11` map. Downstream edits are notes only (see Cross-Domain Dependencies).

### SK.01.CoreConformance — Conform Foundation to the observability gold standard `○`

**Work order:** WO-087 / P-600 · **Depends on:** SK.01.ObservabilityHelpers (P-580), SK.16.TelemetryCapture (P-581), SK.00.ObservabilityReportOnly (P-583), SK.01.CoreObservabilityFixes (P-584)

Applies root `CLAUDE.md` "Observability, exceptions and error codes" (L1-L8, T1-T8, E1-E4, C1-C3) to the 13 Foundation packages. Measured state: only `FeatureManagement` logs (one `[LoggerMessage]`, EventId 1301, as an instance partial method of the provider, template without period or quotes, Warning for an unexpected exception); no `ActivitySource` or `Meter` exists in Foundation (grep) and no raw tag literal outside the `Primitives` registries; every `Core` exception already has the `(Error)`/`(Error, Exception)` pair (P-584 completes the set); the remaining work is the code renames, the sub-block ownership table, the error factories, and exception messages and types. **Breaking, wire-visible, pre-GA, no aliases (WO-087 decision 2):** `ErrorCodes.Unexpected.Default` `unexpected.exception` to `unexpected.default`; `ErrorCodes.Domain.RuleViolated` `domain.rule.violated` to `domain.rule_violated`; FluentValidation pass-through codes (PascalCase validator names) become `ErrorCodes.Validation.*`; `data_privacy.temporarily_unavailable` becomes `data_privacy.unavailable` with `ErrorType.Unavailable` (C3). Telemetry: the domain's reserved name is `SharedKernel.Core`; because Foundation emits no spans or instruments of its own (it adds events to the caller's ambient `Activity` through the `Primitives` recorder and OpenFeature's `TraceEnricherHook`), T1-T6 hold vacuously and the phase records that, and any future Foundation instrument is named `SharedKernel.Core.*` with a public `const` in the emitting assembly. **Stored/wire formats:** the renamed codes are wire strings (ProblemDetails `code`, gRPC rich status, SignalR message prefix, translation keys, dashboards); `PrivacyTaxonomy`, `EncryptedPayload`/`EnvelopePayload` bytes, PHC strings, the compression frame, `WellKnown*` and `TenantId` are untouched.

**Blast radius.** `unexpected.exception` is read by `14` (`ErrorPresentation`, WebApi README row 357, SignalR and gRPC factories and their tests) and by consumer translation catalogs (`Error` remarks: a translation entry pointing at the old code is a rename); `domain.rule.violated` by `03` (the code is an `ErrorCodes` constant: no literal expected, verify); `data_privacy.*` by implementers of `IDataSubjectRequestHandler` (services). All additive-looking constants change value, so each consumer needs only a rebuild plus notes. `PublicAPI.Shipped.txt` carries `const` values: a changed value is a `*REMOVED*` plus an Unshipped line.
