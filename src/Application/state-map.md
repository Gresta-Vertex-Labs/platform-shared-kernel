### SK.05.ApplicationConformance — Conform Application to the observability gold standard `○`

**Work order:** WO-087 / P-603 · **Depends on:** SK.05.PipelineTelemetryGaps (P-586), SK.01.ObservabilityHelpers (P-580), SK.16.TelemetryCapture (P-581), SK.00.ObservabilityReportOnly (P-583); soft: SK.13.WildcardTelemetry (P-582, only for the doc wording of the deleted `WithApplicationTelemetry`)

Applies root `CLAUDE.md` "Observability, exceptions and error codes" (L1-L8, T1-T8, E1-E4, C1-C3) to the four Application packages, on top of the new code of SK.05.PipelineTelemetryGaps. Measured state: the domain already owns one 100-wide sub-block per package (5000 Application with no logging, 5100 Pipeline, 5200 Pipeline.Caching, 5300 MediatR with no logging) and builds every EventId from `LoggingEventIdRanges.Application + n`; the `[LoggerMessage]` methods sit inside each behavior class with sentence-less templates; `LoggingBehavior` uses `ILogger<TRequest>` (a consumer category) and logs a successful request at Information; `TracingBehavior` hand-writes `SetStatus`/`error.*`/`AddException` and gives the exception message as the status description, and records cancellation as an error; `MetricsBehavior` and `TracingBehavior` use the raw literals `request.type`, `request.kind`, `outcome`, `error.type`; `ResponseOutcome` declares its own `success`/`failure`/`exception` strings; cache telemetry uses the keys `sharedkernel.query.type`, `sharedkernel.cache.scope`, `sharedkernel.cache.outcome`, `sharedkernel.command.type`, `sharedkernel.cache.target` (raw `"key"`/`"tag"`), `sharedkernel.cache.evicted`, tags values from `Enum.ToString()` (PascalCase), and the meter name `"SharedKernel.Application"` is declared as a literal in two packages (and a third time in `ApplicationPipelineTestHarness`); the `ActivitySource` and `Meter` carry no version; four swallowed failures leave no trace on any span. Caching instruments already declare units (`{query}`, `{entry}`); what is wrong is their names, tag keys and tag values. **Breaking, wire-visible, pre-GA, no aliases (WO-087 decision 2):** span name, tag keys, tag values, cache instrument names, the exception status description, the success log level, log categories and templates. **Stored/wire formats:** the idempotency key layout label (rule 14) and the cache key format (rule 18) are untouched.

**Blast radius.** The meter and source names do not change (`SharedKernel.Application`), so `AddServiceDefaults`' wildcard (P-582) needs nothing from this phase. Dashboards or alerts keyed on `request.type`/`request.kind`, the cache instrument names or tags, a log filter configured per request-type category, and a trace query on the old span name need the new names. `ApplicationPipelineTestHarness` (same domain) changes its capture implementation; its public members are kept. 13.ServiceDefaults' `ApplicationTelemetryExtensions` is deleted by P-582, not here.
