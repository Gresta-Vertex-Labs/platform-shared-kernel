### SK.06.PersistenceConformance — Conform Persistence to the observability gold standard `○`

**Work order:** WO-087 / P-604 · **Depends on:** SK.01.ObservabilityHelpers (P-580), SK.16.TelemetryCapture (P-581), SK.00.ObservabilityReportOnly (P-583), SK.06.PersistenceErrorSafety (P-587)

Applies every applicable rule of root `CLAUDE.md` "Observability, exceptions and error codes" (L1-L8, T1-T8, E1-E4, C1-C3) to the six packages. **Measured state.** Telemetry: four `Meter` objects and two `ActivitySource`s under three names (`SharedKernel.Persistence` twice — `PersistenceMeter` in EfCore and a second `Meter` in Abstractions' `CrossTenantScopeDiagnostics` —, `...EfCore.Auditing` for both meter and source, `...EfCore.Encryption` meter); instruments `persistence.*`, `audit.*` and `persistence.encryption.*` with `ms` or no unit and no `sharedkernel.` prefix; Auditing and Encryption expose their names as public constants (`AuditingMeter.MeterName`/`ActivitySourceName`, `EncryptionMeter.Name`); repository spans are named `{Aggregate}.{Method}Async` with the `persistence.outcome` tag, `error.type` = exception short name and no recorder; audit spans `audit.checkpoint|seal|verify` and raw tag literals (`audit.resource_type`, `audit.sealed_records`, `reason`, `operation`, `audit.failure_kind`). Logging: bare `LoggingEventIdRanges.Persistence + n` literals in all six packages; EfCore owns 6000-6026 plus `RowLevelSecurityLog` at 6350-6351 inside Npgsql's range; three EfCore log classes; `this ILogger` extension methods in Npgsql and Dapper; `AuditingLog` is public; categories `typeof(TContext)` (`PostgresPersistenceExtensions`) and `GetType()` (`SharedKernelDbContext`) are consumer types; `ILogger<…>? logger = null` optional dependencies; templates with free-text `{Reason}`, `{Problem}`, `{Finding}`, an unquoted `{KeyId}`, em-dashes and `key=value` parentheticals. Error codes: `Persistence.Encryption.KeyNotFound|TenantKeyShredded|TenantShredIncomplete` and `Persistence.BulkMutation.UnsupportedSpecification` are PascalCase; the other codes are lowercase but declared in five places (`PostgresClassifiedErrorCodes`, `ConcurrencyVersion.ConflictErrorCode`, `TenantIsolationErrors.Code`, `AuditChainIntegrityException.ErrorCode`, each exception's `ErrorCode`). Messages: about 54 files with "cannot", 167 throw sites, `PostgresPersistenceExtensions` embeds `ex.Message` into a `ValidateOptionsResult`. **Stored/wire formats:** AUDITv3 bytes, field encryption v3 bytes, version `0x01`, SQL schema and role script are untouched; the *metric, span, tag, error-code and EventId* names are the wire-visible changes. **Breaking, pre-GA, no aliases:** meter and source names (`...EfCore.Auditing`, `...EfCore.Encryption` disappear into `SharedKernel.Persistence`), every instrument name and unit, span names, the `persistence.outcome` tag, four PascalCase error codes, the two public meter-name constants, and EventIds 6350-6351.

## Cross-Domain Dependencies

- **Inbound, 01.Core:** SK.01.ObservabilityHelpers (`TelemetryVersion`, `ActivityFailureExtensions`, `WellKnownOutcomes`, `LoggingEventIdRanges.PackageSubBlockWidth/SubBlockStart/IsInSubBlock`) is a hard dependency of both phases; SK.01.CoreObservabilityFixes makes `TransactionRolledBackException` a `SharedKernelException` (`execution.transaction_rolled_back`, `Unexpected`) and adds Execution -> Core, so `Persistence.Abstractions` inherits Core transitively (Dapper takes an explicit Core reference in SK.06.PersistenceErrorSafety).
- **Inbound, 03.Domain:** SK.03.DomainErrorCodes turns a stored `Money` amount with excess decimals into `DomainException`/`Unexpected` (500) instead of `BusinessRuleViolationException` (422); SK.06.PersistenceErrorSafety T-06 pins the new type.
- **Inbound, 16.Testing:** SK.16.TelemetryCapture (`ActivityRecorder`, `MetricRecorder`, log assertions) is used by every telemetry and log test of both phases.
- **Inbound, 00.Governance:** SK.00.ObservabilityReportOnly must show zero Persistence findings (SK.06.PersistenceConformance T-05).
- **Outbound, 13.ServiceDefaults:** after SK.13.WildcardTelemetry `WithPersistenceTelemetry` keeps only `Npgsql`; until then it names `SharedKernel.Persistence.EfCore.Auditing` and `.Encryption`, which SK.06.PersistenceConformance removes (nothing is dropped meanwhile: the folded name `SharedKernel.Persistence` is already subscribed). `PersistenceReadmeSampleTests` must not name a removed meter or error code.
- **Outbound, 14.Presentation:** 57014 now answers `Timeout` (504); audit record not-found answers 404 and no-tenant 403 (`persistence.tenant_required`); decrypt failures remain 500 but carry `persistence.encryption.*` codes. Presentation maps by `Error.Type`, so no change is expected; confirm `ErrorTypeStatusCodeMap` covers `Timeout`.
- **Outbound, 18.Idempotency / 07.Messaging:** `Idempotency.EfCore` and `Messaging.MassTransit.EfCore` build on `Persistence.EfCore`; neither catches `KeyNotFoundException`, `CryptographicException` or the changed classifier types (verified by grep at planning time). Release notes list the renamed meters, instruments, codes and EventIds for dashboards.
