### SK.10.IntelligenceObservability — Make the AI domain observable and stop its leaks `○`

**Work order:** WO-087 / P-591 · **Depends on:** SK.01.ObservabilityHelpers (P-580: `IHasError`, `TelemetryVersion.Of`, `ActivityFailureExtensions`, `WellKnownOutcomes`, `WellKnownTagKeys.Outcome`; `IntelligenceStreamException` becomes a `SharedKernelException`, which implements `IHasError`), SK.16.TelemetryCapture (P-581: `ActivityRecorder`/`MetricRecorder`, log assertions), SK.13.WildcardTelemetry (P-582: the `SharedKernel.*` subscription and the seconds-histogram view that make the new instruments reach a host; `WithIntelligenceTelemetry()` is deleted there). This phase adds its own explicit `SharedKernel.Core` reference to `.Abstractions`, as `SK.09.SearchErrorSafety` does, instead of relying on `Execution` bringing it transitively.

Fixes the Phase 1 defects found in this domain (audit Part 1, items 1, 5, 6, 7, 8, 9, 10), verified on disk. (1) **Telemetry is declared and never used.** `QdrantDiagnostics` and `SemanticKernelDiagnostics` each create an `ActivitySource` and a `Meter` named `SharedKernel.AI`; nothing starts a span or records a measurement, and the `ai.provider`, `ai.collection`, `ai.model` keys in `IntelligenceWellKnown` have no user, so even a host that subscribes sees nothing, and token usage (rule 7) is returned but never counted. (2) **Provider text reaches `Error.Message`, and so ProblemDetails.** `QdrantErrors.FromException` puts `qdrant.Message`, `exception.Message` and `rpc.Status.Detail` into `EngineFault` and `InvalidQuery`; `SemanticKernelErrors.FromException` puts `exception.Message` into `CompletionFailed` and `EngineFault` (a connector message can echo the endpoint, the deployment name, or request fragments). `IntelligenceErrors.Unreachable(provider, endpoint)` is called with the **collection name** in the endpoint slot (message: "Provider 'qdrant' at 'orders' is unreachable."), and `Timeout(operation, elapsed)` is always called with `TimeSpan.Zero` ("timed out after 00:00:00"). (3) **Logs carry what rule 10 forbids and lose what L4 requires.** `QdrantVectorCollection.Reject` logs `Error.Message` as `{Reason}` (event 10106), and that text embeds the record id for `InvalidRecordId` (rule 10: keys are never logged); `QdrantClientConfigured` (10100) logs `{Host}:{Port}`; no `*Log` method takes an `Exception`, so `QdrantEngineFault` (10113), `SemanticKernelEngineFault` (10307), `QdrantProbeDegraded` (10111) and the retry warning (10309) drop the stack. (4) **Wrong `ErrorType`.** `intelligence.unreachable`, `intelligence.timeout`, `intelligence.write_timeout` and `intelligence.rate_limited` are `Unexpected` (HTTP 500), although the `ErrorType` contract says a dependency that is down, throttling or too slow is `Unavailable` or `Timeout`. (5) **Catch-all swallows defects and mishandles cancellation.** All 18 Qdrant catch sites (nine in `QdrantVectorCollection`, seven in `QdrantCollectionProvisioner`, the hybrid and quantization accessors) and the three SemanticKernel sites use `catch (Exception ex) when (ex is not OperationCanceledException)` and answer `engine_fault`/`completion_failed` for everything else: a `SwitchExpressionException`, `NullReferenceException` or mapping defect becomes a soft failure; and the filter keys on the exception type, not on the caller's token, so (a) a caller's cancellation that surfaces as something other than `OperationCanceledException` (gRPC reports a cancelled call as `RpcException(StatusCode.Cancelled)` unless `ThrowOperationCanceledOnCancellation` is set; D-03 verifies) is mapped to `engine_fault`, and (b) an HTTP-client timeout, which surfaces as `TaskCanceledException` with the caller's token **not** cancelled, escapes as a raw exception from a `Result` API instead of `intelligence.timeout`. (6) **The chat mapper may never match.** Chat goes through Semantic Kernel's `IChatCompletionService`, whose OpenAI connector converts the SDK's `ClientResultException` into `HttpOperationException`; `SemanticKernelErrors` and `IsTransientFailure` test only for `ClientResultException` (the unit tests construct that type directly, bypassing the connector). If D-03 confirms it, every real 401, 404 and 429 on the chat path is `completion_failed` and the rule-8 bounded retry never fires. (7) **`IntelligenceStreamException` derives `Exception`,** so the HTTP, gRPC and SignalR edge maps answer 500 and lose its `Error`. (8) **Possible hidden SDK retry.** The `OpenAIClientOptions` built in `AddSharedKernelSemanticKernel` sets only transport and endpoint; the System.ClientModel pipeline's default retry policy is expected to retry 408/429/5xx up to three times underneath `CompleteAsync` and `EmbedManyAsync`, which would break rule 8 ("always dispatches fresh"), re-bill invisibly, and make the new span duration and token counters lie; D-06 verifies and, if confirmed, disables it.

Policy, aligned with Messaging and Search (`SK.07.MessagingErrorSafety`, `SK.09.SearchErrorSafety`): only a recognised provider fault becomes a `Result` failure; anything else is not caught at all (exception filters, so the original stack is untouched); the caller's cancellation always propagates as `OperationCanceledException`. Unchanged: rules 1–5 and 9–23 in substance (model identity, tenancy, pre-I/O rejection, fingerprint, filter translation), every record payload, point id, fingerprint and alias format, every error code **string** (Phase 2 owns renames), and the `Unauthorized` ErrorType of `intelligence.unauthorized` (Phase 2 owns it).

**Stored/wire formats:** none touched. Wire-visible and listed as breaking: `Error.Message` text of every provider-derived error, the `ErrorType` of four codes (HTTP 500 becomes 503/504), `IntelligenceErrors.Unreachable`, `Timeout` and `EngineFault` signatures, the `{Reason}` and `{Host}`/`{Port}` log placeholders, `IntelligenceStreamException`'s base type, the raw-exception behaviour for unclassified faults, and (if D-06 confirms) the loss of the SDK's implicit retry. Additive: the three instruments, the span names, `ai.operation`/`ai.token_type` keys.

**Per-provider behaviour.** Qdrant classifies gRPC status codes, SemanticKernel classifies HTTP statuses and transport faults, so the classify step is provider-specific while the outcome is identical: a given condition yields the same `Error.Code` and `ErrorType` on both (and on the next provider). Token counters exist only on the SemanticKernel provider (a vector database bills no tokens); the duration histogram, spans and the failure recorder are shared in shape. Tenant isolation and model identity (rules 2–5) are untouched and evaluated before any span would have been dispatched to I/O, so a pre-I/O rejection still performs no I/O (its span ends with the classified failure and no child I/O).

**Design.**

*Error text contract (D-04).* `Error.Message` may contain only kernel-authored wording plus bounded identifiers: provider, operation, collection and model names (configuration, not tenant data), the caller's own record id where the factory already takes it as a typed parameter, a numeric dimension, an HTTP status, and a gRPC status name. It never contains an exception message, `RpcException.Status.Detail`, a connector or response body, an endpoint or host, a filter value, an API key or prompt text. The detail is not lost: it reaches the log through the exception parameter (L4), at the trust level of logs.

| Site | Today | After |
| --- | --- | --- |
| `QdrantErrors` `QdrantException` and default arm | `EngineFault(…, qdrant.Message / exception.Message)` | classified per D-03 or not caught; a recognised fault becomes `EngineFault` with the bounded `engineErrorCode` (gRPC status name) |
| `QdrantErrors` `InvalidArgument` / `FailedPrecondition` | `InvalidQuery(rpc.Status.Detail)` | `InvalidQuery` with fixed kernel text plus the status name |
| `SemanticKernelErrors` default and ≥ 500 arms | `exception.Message` into `CompletionFailed` / `EngineFault` | fixed text plus the HTTP status |
| `IntelligenceErrors.Unreachable(provider, endpoint)` | endpoint slot filled with the collection name | `Unreachable(provider)`: the parameter is removed (breaking) |
| `IntelligenceErrors.Timeout(operation, elapsed)` | always `TimeSpan.Zero` | `Timeout(operation)`: the parameter is removed (breaking). `WriteTimeout` keeps its elapsed (a real measured wait) |
| `IntelligenceErrors.EngineFault(provider, operation, detail)` | free text | `engineErrorCode` nullable, bounded token; XML doc states it |
| `reason` parameters of `InvalidQuery`, `InvalidFilter`, `InvalidCollectionDefinition`, `WriteRejected`, `CutoverFailed`, `ProbeFailed`, `CompletionFailed` | any string | signatures kept; XML docs state "kernel-authored text, never provider or exception text"; Phase 2 closes them |

*ErrorType table (D-04).* `unreachable` becomes `Unavailable`; `timeout` and `write_timeout` become `Timeout`; `rate_limited` becomes `Unavailable` (the `ErrorType` contract classes a throttling dependency as `Unavailable`; there is no rate-limit member, recorded as a note to 01.Core). Nothing else changes type this phase.

*Classify-or-rethrow table (D-03).* The implementer verifies every row against the pinned packages (`Qdrant.Client` 1.18.1, `Microsoft.SemanticKernel` and `Connectors.OpenAI` 1.78.0, `OpenAI` 2.10.0, `System.ClientModel` 1.10.0) and amends the table before coding. The cancellation rule is evaluated first and on the **caller's token**, not on the exception type.

| Exception or response | Qdrant | SemanticKernel | Outcome |
| --- | --- | --- | --- |
| caller's token cancelled, whatever exception surfaced (`OperationCanceledException`, `RpcException(Cancelled)`, wrapped) | propagate | propagate | `OperationCanceledException` whose token is the caller's |
| `OperationCanceledException`/`TimeoutException`/`TaskCanceledException`, caller's token **not** cancelled | n/a (deadline arrives as `DeadlineExceeded`) | HTTP-client or pipeline timeout | `intelligence.timeout` |
| `RpcException` `DeadlineExceeded` | yes | n/a | `intelligence.timeout` |
| transport fault | `RpcException` `Unavailable` | `HttpRequestException` or `ClientResultException`/`HttpOperationException` without a status; 502, 503, 504 | `intelligence.unreachable` (`Unavailable`) |
| throttling | `ResourceExhausted` | 429 | `intelligence.rate_limited` (`Unavailable`) |
| auth | `PermissionDenied`, `Unauthenticated` | 401, 403 | `intelligence.unauthorized` (type unchanged; Phase 2) |
| known rejection | `NotFound`, `AlreadyExists`, `InvalidArgument`, `FailedPrecondition` | 404 (`model_not_found`) | existing mapped codes, text per D-04 |
| 408 | n/a | yes | `intelligence.timeout` |
| unknown rejection from the provider (other gRPC status, other 4xx/5xx) | `Internal`, `Unknown`, `DataLoss`, `Unimplemented`, `Aborted`, `OutOfRange`; `QdrantException` per D-03 | other statuses | `intelligence.engine_fault` / `completion_failed` with the bounded code |
| payload (de)serialization of a provider response (`JsonException`) | n/a | yes | classified: `engine_fault` |
| `SwitchExpressionException`, `InvalidOperationException`, `ArgumentException`, `NullReferenceException`, `InvalidCastException`, a record-mapping fault, SK `KernelException` raised before any I/O, any other | **not caught** | **not caught** | a defect or misconfiguration; propagates with its original stack |

*Streams (D-03).* `ScrollAsync` and `CompleteStreamingAsync` apply the same table: a classified fault throws `IntelligenceStreamException` (carrying the mapped `Error`, inner exception kept), an unclassified one propagates untouched, caller cancellation is `OperationCanceledException`. `[EnumeratorCancellation]` stays. The tenant-scope throw in `ScrollAsync` stays a `IntelligenceStreamException`.

*Telemetry (D-02).* New instruments and spans are created with their final gold-standard names, so Phase 2 never renames them. Per provider an internal `QdrantTelemetry` / `SemanticKernelTelemetry` (replacing `…Diagnostics`): `ActivitySource` static (T1), `Meter` from `IMeterFactory` (registered by the builders; two providers asking the same factory for the same name share one meter and stay separable by `ai.provider`), both named `IntelligenceWellKnown.ActivitySourceName`/`MeterName` (`SharedKernel.AI`) and versioned `TelemetryVersion.Of(typeof(…).Assembly)`.

| Instrument | Kind | Unit | Tags |
| --- | --- | --- | --- |
| `sharedkernel.ai.operation.duration` | histogram (double) | `s` | `ai.provider`, `ai.operation`, `ai.collection` (vector operations), `ai.model` (embeddings and completions), `outcome` (`WellKnownTagKeys.Outcome`, values from `WellKnownOutcomes`), `error.type` (not on success: `ErrorType` name or exception full name) |
| `sharedkernel.ai.tokens` | counter (long) | `{token}` | `ai.provider`, `ai.operation`, `ai.model`, `ai.token_type` (`input`, `output`) |
| `sharedkernel.ai.vector.records` | counter (long) | `{record}` | `ai.provider`, `ai.operation`, `ai.collection`, `outcome` (`success`/`failure`, per record of a write) |

Spans: `ai {operation}` lowercase, kind **Client** for every call that reaches the provider; operations are lowercase snake names declared once as constants (`upsert`, `upsert_many`, `delete`, `delete_many`, `delete_by_filter`, `query`, `query_hybrid`, `get`, `count`, `scroll`, `embed`, `embed_many`, `complete`, `complete_stream`). A pre-I/O rejection still yields a span and a duration observation ending with the classified failure. `EmbedAsync` routes through a private core with its own operation name, so it produces one span, not two. `WaitUntilQueryableAsync` (a no-op on Qdrant) and the readiness probe produce no span (the health request is already a span; Search precedent). Control-plane spans (`ensure_collection`, `cutover`, …) belong to Phase 2. Token counters count only usage the provider actually returned, once per completed call: `input` from `PromptTokens`, `output` from `CompletionTokens` (zero is not recorded); a failed call counts nothing; a stream counts once with the usage its chunks carried (D-02 settles last-versus-sum against the real chunk shape; no double count). Failure recording only through the shared recorder: a classified failure → `RecordFailure`/`RecordResult` (status `Error`, `error.code`, `error.type` = `ErrorType`), an unclassified exception → `RecordException` (full exception event; traces share the trust level of logs), caller cancellation → no error status, outcome `canceled`, duration still recorded. Tag values are bounded configuration only: provider, collection and model names, never a record id, vector, filter value, query text, prompt or completion text, metadata value, API key or host (rule 10, proven by a sentinel test); `ai.model` on a metric is the resolved model id only when it is a model the descriptor reports, otherwise `_OTHER`, because `CompletionRequest.ModelId` is caller-supplied (D-02 reads the descriptors and fixes the mechanism). A streaming span is ended when the enumerator completes, faults or is disposed (an abandoned stream still ends its span), and `Activity.Current` is restored around each `yield` so the consumer's ambient activity is never replaced (D-02 pins this with a test).

If confirmed, `AddSharedKernelSemanticKernel` sets a no-retry policy so the one retry the package offers is `WithBoundedRetry` (rule 8) and `CompleteAsync` dispatches exactly once without it. This is a behaviour change (callers lose an invisible retry) and is listed under "Breaking changes". If the default is not what is expected, record the finding in the task notes and drop C-07's retry part.

### SK.10.IntelligenceConformance — Conform Intelligence to the observability gold standard `○`

**Work order:** WO-087 / P-608 · **Depends on:** SK.10.IntelligenceObservability (P-591), SK.01.ObservabilityHelpers (P-580: `TelemetryVersion`, the recorder, `WellKnownOutcomes`, `LoggingEventIdRanges.SubBlockStart/IsInSubBlock`), SK.16.TelemetryCapture (P-581: `ActivityRecorder`/`MetricRecorder`, log assertions), SK.13.WildcardTelemetry (P-582: the wildcard subscription and the seconds-histogram view; `WithIntelligenceTelemetry()` is deleted), SK.00.ObservabilityReportOnly (P-583: the report this phase must clear).

Applies every applicable rule of root `CLAUDE.md` "Observability, exceptions and error codes" (L1–L8, T1–T8, E1–E4, C1–C3) to the four Intelligence packages. Applicability: T7 (client-facing error ids) and T8 (propagation) do not apply (no HTTP surface, no propagated headers); E1 for exceptions other than `IntelligenceStreamException` does not apply (it is the only exception type, handled in Phase 1). Phase 1 already created the instruments, spans and tags with their final names, so this phase pins, relocates and completes them; it renames no instrument. Everything below that is wire- or dashboard-visible is carried in the release notes. Unchanged: filter semantics, tenancy, model identity, rules 1–23 in substance, every payload, id, fingerprint and alias format, and the EventId numbers.

**Stored/wire formats:** none touched. Wire-visible and breaking: error code strings and four `ErrorType`s (below), the three public tag-name constants leaving `IntelligenceWellKnown`, public `IntelligenceErrors` members renamed, rewritten log templates (log-query impact; EventIds unchanged). Additive: `IntelligenceErrorCodes`, `IntelligenceTagKeys`, control-plane spans.

**Per-provider behaviour.** Every code, `ErrorType`, span name, tag, operation constant and instrument name is identical for both providers and for any future vector provider; the shared constants live in `.Abstractions`, so identity holds by construction. Phase 1 chose, and this phase keeps, one `ActivitySource` (static) and one `Meter` (from `IMeterFactory`) **per provider assembly under the single domain name `SharedKernel.AI`**: this is what "unify the two providers' diagnostics classes under `SharedKernel.AI`" means here, because `.Abstractions` may not own an `ActivitySource` (Packages row, `PackagePurityTests`) and a shared instance would need a package edge between siblings (rule 13). Both classes are named `{Provider}Telemetry`, take every name from `IntelligenceWellKnown`/`IntelligenceTagKeys`/`IntelligenceOperations`, and are exercised by the same convention assertions. Swapping providers changes no dashboard except the `ai.provider` tag value.

**Design.**

*Error codes (C1–C3).* A public `IntelligenceErrorCodes` (Abstractions) holds every code as a `const string`; `IntelligenceErrors` builds `Error` values from it and **stays public** (the two providers and the double are separate assemblies that construct the same vocabulary; an `InternalsVisibleTo` from Abstractions would name its siblings, rule 13; the same deviation `SK.09.ObservabilityConformance` D-01 records, flagged to `arch-lead` for a C2 amendment). The providers' `QdrantErrors`/`SemanticKernelErrors` are internal mappers and stay internal; a provider gets its own `…ErrorCodes` class only when it introduces a provider-exclusive code (none exists).
