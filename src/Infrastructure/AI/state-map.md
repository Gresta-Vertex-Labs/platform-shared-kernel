### SK.10.IntelligenceConformance — Conform Intelligence to the observability gold standard `○`

**Work order:** WO-087 / P-608 · **Depends on:** SK.10.IntelligenceObservability (P-591), SK.01.ObservabilityHelpers (P-580: `TelemetryVersion`, the recorder, `WellKnownOutcomes`, `LoggingEventIdRanges.SubBlockStart/IsInSubBlock`), SK.16.TelemetryCapture (P-581: `ActivityRecorder`/`MetricRecorder`, log assertions), SK.13.WildcardTelemetry (P-582: the wildcard subscription and the seconds-histogram view; `WithIntelligenceTelemetry()` is deleted), SK.00.ObservabilityReportOnly (P-583: the report this phase must clear).

Applies every applicable rule of root `CLAUDE.md` "Observability, exceptions and error codes" (L1–L8, T1–T8, E1–E4, C1–C3) to the four Intelligence packages. Applicability: T7 (client-facing error ids) and T8 (propagation) do not apply (no HTTP surface, no propagated headers); E1 for exceptions other than `IntelligenceStreamException` does not apply (it is the only exception type, handled in Phase 1). Phase 1 already created the instruments, spans and tags with their final names, so this phase pins, relocates and completes them; it renames no instrument. Everything below that is wire- or dashboard-visible is carried in the release notes. Unchanged: filter semantics, tenancy, model identity, rules 1–23 in substance, every payload, id, fingerprint and alias format, and the EventId numbers.

**Stored/wire formats:** none touched. Wire-visible and breaking: error code strings and four `ErrorType`s (below), the three public tag-name constants leaving `IntelligenceWellKnown`, public `IntelligenceErrors` members renamed, rewritten log templates (log-query impact; EventIds unchanged). Additive: `IntelligenceErrorCodes`, `IntelligenceTagKeys`, control-plane spans.

**Per-provider behaviour.** Every code, `ErrorType`, span name, tag, operation constant and instrument name is identical for both providers and for any future vector provider; the shared constants live in `.Abstractions`, so identity holds by construction. Phase 1 chose, and this phase keeps, one `ActivitySource` (static) and one `Meter` (from `IMeterFactory`) **per provider assembly under the single domain name `SharedKernel.AI`**: this is what "unify the two providers' diagnostics classes under `SharedKernel.AI`" means here, because `.Abstractions` may not own an `ActivitySource` (Packages row, `PackagePurityTests`) and a shared instance would need a package edge between siblings (rule 13). Both classes are named `{Provider}Telemetry`, take every name from `IntelligenceWellKnown`/`IntelligenceTagKeys`/`IntelligenceOperations`, and are exercised by the same convention assertions. Swapping providers changes no dashboard except the `ai.provider` tag value.

**Design.**

*Error codes (C1–C3).* A public `IntelligenceErrorCodes` (Abstractions) holds every code as a `const string`; `IntelligenceErrors` builds `Error` values from it and **stays public** (the two providers and the double are separate assemblies that construct the same vocabulary; an `InternalsVisibleTo` from Abstractions would name its siblings, rule 13; the same deviation `SK.09.ObservabilityConformance` D-01 records, flagged to `arch-lead` for a C2 amendment). The providers' `QdrantErrors`/`SemanticKernelErrors` are internal mappers and stay internal; a provider gets its own `…ErrorCodes` class only when it introduces a provider-exclusive code (none exists). Renames:

| Today | After | `ErrorType` | Why (rule) |
| --- | --- | --- | --- |
| `intelligence.unreachable` (`Unreachable`) | `intelligence.unavailable` (`Unavailable`) | Unavailable | C3 reason word for an outage |
| `intelligence.unsupported_capability` | `intelligence.not_supported` | Validation | C3 reason word |
| `intelligence.engine_version_unsupported` | `intelligence.engine_version_not_supported` | Unexpected | C3 reason word |
| `intelligence.unauthorized` (`Unauthorized`) | `intelligence.engine_unauthorized` (`EngineUnauthorized`) | **Unexpected** (was Unauthorized) | Every producer is a provider rejecting the kernel's own key (PermissionDenied, Unauthenticated, 401, 403): a deployment defect (C3), and answering the end user 401 sends clients into re-authentication loops. `intelligence.tenant_scope_missing` keeps `Unauthorized` (fail-closed isolation, rule 4) |
| `intelligence.timeout`, `write_timeout`, `rate_limited` | unchanged codes | Timeout, Timeout, Unavailable | already corrected in Phase 1 |
| `intelligence.write_rejected`, `engine_fault`, `completion_failed`, `probe_failed`, `bulk_partially_failed` | unchanged | Unexpected | kept: without provider text the kernel cannot tell a caller's bad record from drift |

All other codes already match `intelligence.{snake_reason}` and keep their `ErrorType`. An enumerating pinning test asserts lowercase prefix, snake case, uniqueness and exactly one literal `ErrorType` per code, so a new code fails until mapped. The `reason` parameters left from Phase 1 (`InvalidQuery`, `InvalidFilter`, `InvalidCollectionDefinition`, `WriteRejected`, `CutoverFailed`, `ProbeFailed`, `CompletionFailed`) become closed vocabularies where the caller set is closed (D-01 lists them); message wording is rewritten to E3 (sentences, trailing period, quoted values, "must not", no `'{provider}''s'` possessive).

*Telemetry (T1, T3–T6).* `IntelligenceTagKeys` (public, Abstractions) holds `ai.provider`, `ai.collection`, `ai.model`, `ai.operation`, `ai.token_type`; the three tag-name constants leave `IntelligenceWellKnown`, which keeps the source and meter names, provider names and query limits (root T4 puts package keys in `{Capability}TagKeys`; the P-608 phrase "complete in the well-known class" is read as "complete and constant-backed", and rule 21 is reworded accordingly, flagged to the caller). `IntelligenceOperations` (introduced in Phase 1) is final. New control-plane spans in `SharedKernel.AI.Qdrant`: `ai ensure_collection`, `ai collection_exists`, `ai delete_collection`, `ai cutover`, `ai quantization_profile`, kind Client, same tag set (`ai.provider`, `ai.operation`, `ai.collection`), same recorder; the same duration histogram observes them. No span for the readiness probe (Phase 1 D-05). Cutover's two-step alias swap is one span. The convention assertions (`ShouldFollowSpanConvention`, `ShouldFollowMetricConvention`) run over both providers.

*Logging (L1–L8).* Sub-blocks stay: `AI.Abstractions` 10000–10099 (reserved, unused), `AI.Qdrant` 10100–10199, 10200–10299 explicitly reserved for the next vector provider, `AI.SemanticKernel` 10300–10399; no id is renumbered. `Logging/` moves to `Diagnostics/`; each provider gets `internal static class QdrantLoggingEventIds` / `SemanticKernelLoggingEventIds` (`LoggingEventIdRanges.Intelligence + n`, no bare literal in an attribute) and its `*Log` class becomes plain static partial methods (`QdrantLog.CollectionEnsured(logger, …)`, not `this ILogger`). Templates are rewritten to the L3 shape: one sentence, trailing period, quoted identifiers, `{ElapsedMilliseconds}`, `{ErrorType}`/`{ErrorCode}`; the offenders are the `Reachable=… CollectionAddressable=…` key=value probe line (10111), `{DurationMs}` (10105), the colon-and-clause sentences (10104, 10109), `{Expected}`/`{Actual}` (10112), `{Requested}`/`{Ceiling}`/`{Estimated}` naming and the `after error code '{ErrorCode}'` clause (10309). Categories: every logger is `ILogger<KernelType>` (the collection, provisioner, orchestrator and generator already are; the registration code is swept for string categories and third-party types). Loggers stay required constructor dependencies (L8). Levels follow L6; Phase 1 already moved classified faults to Warning.

*Exceptions (E2, E3).* Programming and configuration errors: `ChatRole` and `VectorDistanceMetric` unknown-value arms in the providers and the double become `UnreachableException`; the orchestrator's "retry loop terminated without a result" `InvalidOperationException` becomes `UnreachableException`; builder and options misconfiguration texts (`QdrantBuilder`, `SemanticKernelBuilder`, registration-order and duplicate-registration messages, definition-build failures that embed `definitionResult.Error.Message`) are rewritten to the E3 phrasing: sentence, quoted values, name the remedy, the nested `Error.Code` instead of its text. `ArgumentException`/`ThrowIf*` guards stay (E2). A grep over the four packages drives the sweep (D-04).
