### SK.09.SearchErrorSafety — Detail leaks, lost exceptions and swallowed failures `○`

**Work order:** WO-087 / P-590 · **Depends on:** SK.01.ObservabilityHelpers (P-580: `IHasError`, the span failure recorder; `SearchStreamException` becomes a `SharedKernelException`, which implements it), SK.16.TelemetryCapture (P-581: the capture helpers T-03/T-07 assert with). P-584 is **not** a dependency: this phase adds its own explicit `SharedKernel.Core` reference, as `SK.07.MessagingErrorSafety` does, instead of relying on `Execution` bringing it transitively.

Fixes the Phase 1 defects found in Search (audit Part 1, items 5, 6, 7, 8 and 9), verified on disk. (1) **Provider text reaches `Error.Message`, and so ProblemDetails.** ElasticSearch puts `response.DebugInformation` (the full request body: query text, filter values, hosts, headers) into `SearchErrors.EngineFault`, `CutoverFailed`, `IndexDefinitionConflict` and `AggregationFailed` at 17 sites (`ElasticSearchResultMapper`, `ElasticSearchIndexProvisioner`, `ElasticSearchCursorSearch`, `ElasticSearchAnalytics`); both providers put `ex.Message` into `EngineFault` (`ElasticSearchIndex.ExecuteAsync`, `ElasticSearchSuggestSearch`, `MeilisearchFaultMapper`), `CutoverFailed` (`MeilisearchIndexProvisioner`) and `TenantTokenIssuanceFailed`; Meilisearch forwards `apiError.Message` (which echoes the filter expression) into `InvalidFilter`, `InvalidSearchRequest` and `EngineFault`; the ES cursor puts the `FormatException` message into `InvalidCursor`. The ES fault mapper already prefers the server's `reason` over `DebugInformation`, but that `reason` is engine free text too (a `query_string` parse error repeats the user's text; a mapping error repeats a field value). `SearchErrors.Unreachable` also embeds the engine endpoint (a host name) in the message. (2) **`Error.Message` is logged as free text** (`ElasticSearchIndex.cs:511`, `MeilisearchIndex.cs:401`, `{Reason}`), and `9100` logs the Meilisearch `{Url}`. (3) **Exceptions are lost:** no `*Log` method takes an `Exception`, so every caught-exception log (`OperationFaulted`, `EngineFault`, the probe degrade, the PIT close failure) drops the stack, and the Meilisearch tenant-token and cutover catches log nothing. (4) **Swallowed failures:** `ElasticSearchCursorSearch.ReadCursorAsync` wraps the search in `catch (Exception)` and answers `CursorExpired` for everything, including the caller's cancellation (breaks rule 13), a 401, a 503 and a serializer fault; it also answers `CursorExpired` for **any** invalid response; `ExecuteAsync` and the suggester turn every exception, including a `SwitchExpressionException` from a translation switch (a defect, rule 11) into `search.engine_fault`; both provisioners' probes use bare `catch` that also swallows cancellation. (5) **`SearchStreamException` does not derive `SharedKernelException`,** so the HTTP, gRPC and SignalR edge maps answer 500 and lose its `Error`. Policy, aligned with Messaging's classify-or-rethrow (`SK.07.MessagingErrorSafety`): only a recognised engine fault becomes a `Result` failure; anything else rethrows with a plain `throw;`; the caller's cancellation always propagates. Unchanged: rules 6–11 (tenancy and pre-I/O rejections), 14, 16–22, every filter translation, and every code string and `ErrorType` in this phase (Phase 2 owns renames).

**Stored/wire formats:** none touched. No index mapping, `_meta` fingerprint, cursor token, alias or document change. The cursor token format is unchanged; only the text of `InvalidCursor` changes. Error-message text changes are wire-visible (ProblemDetails `detail`) and listed as breaking. `search.unreachable` keeps its string; only its message loses the endpoint.

**Per-engine behaviour.** Meilisearch's SDK throws and ElasticSearch's client returns invalid responses, so the classify step is engine-specific while the outcome is identical: a given fault class yields the same `Error.Code`/`ErrorType` on both (rule 12). The rethrow step is the same on both. Nothing here depends on an engine version or on swapping engines; tenant isolation (rules 6–9) is untouched.

**Design.**

*Error text contract (D-02).* `Error.Message` may contain only kernel-authored wording plus bounded identifiers: index, operation and provider names, an HTTP status, and an engine error code (Meilisearch `Code`, ElasticSearch `error.type`, accepted only when it matches `^[a-z0-9_.]{1,64}$`, else omitted). It never contains a response body, `DebugInformation`, a server `reason`, `ex.Message`, an endpoint or host, a cursor token, a query, a filter value or a document id beyond what the factory already takes as a typed parameter. Engine detail is not lost: it reaches the log through the exception parameter (Meilisearch SDK exceptions) or `ApiCallDetails.OriginalException` (ElasticSearch invalid responses), at the trust level of logs.

| Site | Today | After |
| --- | --- | --- |
| ES invalid response, any operation | `EngineFault(…, response.DebugInformation)` and the other three factories | `ElasticSearchFaultMapper.Map`/`MapWrite` (status → code), engine detail reduced to the bounded `error.type`; the log call receives `OriginalException` when present |
| ES `put mapping` / `put settings` / `put alias` failure | always `IndexDefinitionConflict(name, DebugInformation)` or `EngineFault` | 400 → `IndexDefinitionConflict(name, "(unknown)")` (the field is not parsed out of engine text; the placeholder is the one `MeilisearchFaultMapper` already uses); any other status → the mapped outage/timeout/auth error |
| Meilisearch `apiError.Message` | into `InvalidFilter`, `InvalidSearchRequest`, `EngineFault` | fixed kernel wording plus the bounded engine `Code`; the `MeilisearchApiError` itself goes to the log |
| `ex.Message` into `EngineFault`/`CutoverFailed`/`TenantTokenIssuanceFailed` | raw text | fixed reason (`failed step 'swap'`, `signing failed`) plus, for a nested `Error`, its `Code`; the exception goes to the log |
| `SearchErrors.Unreachable(provider, endpoint)` | endpoint in the message | the `endpoint` parameter is removed (breaking); the host is configuration, not a client concern |
| `ElasticSearchErrors.InvalidCursor(ex.Message)` | `FormatException`/`JsonException` text | fixed text; the exception goes to a log |

*Classify-or-rethrow table (D-03).* The implementer verifies each row against the real engines and the SDK versions pinned in `Directory.Packages.props` and amends the table before coding.

| Exception or response | Meilisearch | ElasticSearch | Outcome |
| --- | --- | --- | --- |
| `OperationCanceledException` with the caller's token cancelled | rethrow | rethrow | propagates (rule 13) |
| `OperationCanceledException`/`TaskCanceledException`/`TimeoutException`, caller's token **not** cancelled (HTTP client timeout) | `MeilisearchTimeoutError`, `TimeoutException`, non-caller cancel | `ApiCallDetails.OriginalException` of those types, or a thrown one | `search.timeout` |
| Transport fault | `MeilisearchCommunicationError`, `HttpRequestException` without status, 502/503/504 | no HTTP status, or 429/502/503/504 | `search.unreachable` |
| Auth | 401/403, key-error codes | 401/403 | `search.unauthorized` |
| Engine rejection with a known code or status | `MeilisearchApiError` with a mapped code | 400/404/409 | the existing mapped codes, text per D-02 |
| Engine rejection with an unknown code | `search.engine_fault` with the bounded code | `search.engine_fault` with the bounded `error.type` | unchanged code, safe text |
| Payload (de)serialization of an engine response (`JsonException`) | `search.engine_fault` | `search.engine_fault` | classified: an engine payload the SDK cannot read is an engine-side fact |
| ES document (de)serialization without a source serializer context | not applicable | the STJ "metadata not provided / reflection disabled" exception | `SourceSerializerContextMissing(documentTypeName)`; today the factory exists but nothing produces it (the catch-all gives `engine_fault`), which contradicts the Decisions row; D-03 fixes the exception types to match against the pinned client |
| `SwitchExpressionException`, `ArgumentException`, `InvalidOperationException`, `NullReferenceException`, any other | **rethrow** | **rethrow** | a defect (a new filter node reached an adapter that cannot translate it, rule 11) must not become a soft `Result` failure |

*Telemetry on the rethrow path (D-06).* This phase keeps today's instrument shape (Phase 2 owns names, tags and the recorder). A rethrown exception still completes the span and records the duration histogram: span status `Error` with the exception **type name** as description (never the message), `error.type` = the exception full name, the same tag set as today. Without it, classify-or-rethrow would create a telemetry blind spot where the old catch-all recorded a failure.

*Cursor expiry (D-04).* `ReadCursorAsync` answers `CursorExpired` only for the point-in-time-missing signal. The implementer reproduces it on `ElasticsearchContainerFixture` (a PIT opened with a short keep-alive, read after it lapses, and read after `CloseCursorAsync`), records the exact status and `error.type` the engine returns (expected 404 `search_context_missing_exception`, possibly wrapped in a 400 `search_phase_execution_exception`), and encodes it as a named constant check. Every other invalid response goes through `ElasticSearchFaultMapper.Map` (so a 503 is `search.unreachable` and a 401 is `search.unauthorized`); a thrown exception follows the table above; cancellation propagates.

*Probe measurement (D-05).* The readiness probes (`ProbeAsync`) keep their contract that a failed measurement degrades the report rather than throwing (rule 25): the per-measurement catches become `catch (Exception ex) when (!cancellationToken.IsCancellationRequested)`, the first captured exception is passed to the existing degraded log (9116 / 9219), and caller cancellation propagates. `SearchIndexReadinessProbe` already throws on a cancelled token before the first call; mid-probe cancellation now behaves the same way.

*Logs (D-06).*

| EventId | Change |
| --- | --- |
| 9100 | drop `{Url}` (L5: no URLs or hosts); keep `{IndexCount}` |
| 9110 / 9209 | `{Reason}` (was `Error.Message`) becomes `{ErrorType}` and `{ErrorCode}`; the call passes `error.Type` and `error.Code` |
| 9119, 9123 / 9222, 9225 | take `Exception? exception` last; the callers pass the caught exception (ES: `OriginalException` of an invalid response when present) |
| 9116 / 9219 | take `Exception? exception` last (D-05) |
| 9215 | takes `Exception? exception` last (PIT close failure) |
| **9128** (new, Meilisearch, Warning) | tenant token issuance failed, takes the exception |
| **9129** (new, Meilisearch, Warning) | cutover step failed, `{Step}` plus the exception |
| **9230** (new, ElasticSearch, Warning) | cursor read faulted and was mapped to `{ErrorCode}`, takes the exception |

New ids are the next free ids in each sub-block (9128, 9129, 9230); no id is renumbered or reused. Rethrown, unclassified exceptions are **not** logged by the provider (the caller's handler logs them once); only classified failures log, at Warning (expected failure, L6).

### SK.09.ObservabilityConformance — Conform Search to the observability gold standard `○`

**Work order:** WO-087 / P-607 · **Depends on:** SK.09.SearchErrorSafety (P-590), SK.01.ObservabilityHelpers (P-580: `TelemetryVersion`, the span failure recorder, `WellKnownOutcomes`, `WellKnownTagKeys.Outcome`, `LoggingEventIdRanges.SubBlockStart/IsInSubBlock`), SK.16.TelemetryCapture (P-581: `ActivityRecorder`/`MetricRecorder`, log assertions), SK.13.WildcardTelemetry (P-582: the `SharedKernel.*` wildcard subscription and the one seconds-histogram view; `WithSearchTelemetry()` is deleted), SK.00.ObservabilityReportOnly (P-583: the report this phase must clear).

Applies every applicable rule of root `CLAUDE.md` "Observability, exceptions and error codes" (L1–L8, T1–T8, E1–E4, C1–C3) to the three Search packages and the double. Applicability: T7 (client-facing error ids), T8 (propagation) and E1 for exceptions other than `SearchStreamException` do not apply here (Search has no HTTP surface, sends no propagated headers, and has one exception type, handled in Phase 1). Everything below is wire- or dashboard-visible and is carried in the release notes. Unchanged: filter semantics, tenancy, rules 1–28 in substance, every index/alias/cursor format.

**Stored/wire formats:** no index, mapping, fingerprint, alias or cursor change. Wire-visible and breaking: error code strings and `ErrorType`s (below), metric instrument names, the `error.type` tag value on metrics, the `outcome` tag, `SearchWellKnown` constants moved, public `SearchErrors` members renamed, `ElasticSearchErrors`/`MeilisearchErrors` made internal.

**Per-engine behaviour.** Every code, `ErrorType`, span name, tag and instrument is identical on both providers; the shared constants live in `.Abstractions` (the byte-identity rule stays true by construction). A provider-exclusive code (`search.elasticsearch.*`, `search.meilisearch.*`) lives in its own package's `ErrorCodes` class. No provider-specific behaviour changes. Swapping engines changes no dashboard except the `search.provider` tag value.

**Design.**

*Error codes (C1–C3).* A public `SearchErrorCodes` (Abstractions) holds every code as a `const string`; `SearchErrors` builds `Error` values from it. `ElasticSearchErrorCodes` and `MeilisearchErrorCodes` hold the exclusive codes; `ElasticSearchErrors`/`MeilisearchErrors` become `internal` (single-assembly factories, only codes are a consumer's contract). `SearchErrors` itself stays **public** (D-01 records why and asks `arch-lead` to amend C2's "internal" wording). Renames:

| Today | After | `ErrorType` | Why (rule) |
| --- | --- | --- | --- |
| `search.unreachable` (`Unreachable`) | `search.unavailable` (`Unavailable`) | Unavailable | C3 reason word for an outage |
| `search.unsupported_capability` | `search.not_supported` | Validation | C3 reason word |
| `search.engine_version_unsupported` | `search.engine_version_not_supported` | Unexpected | C3 reason word |
| `search.unauthorized` | `search.engine_unauthorized` | **Unexpected** (was Unauthorized) | The engine rejecting the kernel's own key is a deployment defect (C3: defect = Unexpected); answering the end user 401 sends clients into re-authentication loops. `search.tenant_scope_missing` keeps `Unauthorized` (fail-closed isolation, rule 7) |
| `search.timeout` | unchanged; message drops the always-zero elapsed time | Timeout | E3 |
| `search.write_rejected` | unchanged | Unexpected | kept: without engine text the kernel cannot tell a caller's bad document from a mapping drift (Phase 1 removed the text), so it is not Validation |
| `search.cutover_failed`, `search.index_definition_conflict`, `search.schema_fingerprint_mismatch` | unchanged | Conflict | logical refusals only; an outage during cutover is `search.unavailable` (Phase 1) |

All other codes already match `search.{snake_reason}` and keep their `ErrorType`. A pinning test enumerates every constant: lowercase `search.` prefix, snake case, unique, and each has exactly one `ErrorType` asserted literally.

*Telemetry (T1, T3–T6).* One `ActivitySource` and one `Meter`, both named `SharedKernel.Search` (the public constants stay on `SearchWellKnown`), versioned with `TelemetryVersion.Of(assembly)`. `SearchDiagnostics` (static, duplicated per provider) becomes an internal `SearchTelemetry` per provider: `ActivitySource` static (T1), `Meter` from `IMeterFactory` (the builders register it as a singleton; both providers requesting the same name get the factory's shared meter, distinguished by the `search.provider` tag, and the BothProviders harness proves it). Instruments: `sharedkernel.search.operation.duration` (histogram, `s`) and `sharedkernel.search.documents` (counter, `{document}`) replace `search.client.operation.duration` and `search.client.documents`. Tags: `search.index`, `search.operation`, `search.provider` (constants move from `SearchWellKnown` to a public `SearchTagKeys`), `outcome` (`WellKnownTagKeys.Outcome`, values from `WellKnownOutcomes`), and `error.type` = the `ErrorType` name or the exception full name (was the unbounded-looking error code). Operation names move from two duplicated private lists to a public `SearchOperations` constants class (lowercase snake, identical on both providers). Spans: `search {operation}` lowercase, kind Client for every call that reaches the engine; the existing index/search spans plus new spans for the provisioner (`ensure_index`, `delete_index`, `cutover`, `verify_indexes`), the cursor (`open_cursor`, `read_cursor`, `close_cursor`, `stream`), analytics (`aggregate`), instant search (`instant_search`) and tenant-token issuance (`issue_tenant_token`, kind Internal, no I/O). No span for the readiness probe (Phase 1 D-05). Failure recording only through the shared recorder: classified failure → `RecordResult`/`RecordFailure` (status Error, `error.code`, `error.type` = `ErrorType`), unclassified exception → `RecordException` (full exception event, `AddException`, traces share the trust level of logs), caller cancellation → no error status, outcome `canceled`, duration still recorded. The query text, filter values, document ids and cursor tokens are never tags (rule 28), proven by a sentinel test.

*Logging (L1–L8).* Per-package sub-blocks already exist and stay (Abstractions 9000–9099 reserved and unused, Meilisearch 9100–9199, ElasticSearch 9200–9299); no id is renumbered. `Logging/` moves to `Diagnostics/`; each package gets `internal static class MeilisearchLoggingEventIds` / `ElasticSearchLoggingEventIds` (`LoggingEventIdRanges.Search + n`, no bare literal in an attribute) and its `*Log` class becomes plain static partial methods (`MeilisearchLog.IndexEnsured(logger, …)`, not `this ILogger`). Templates are rewritten to the L3 shape: one sentence, trailing period, quoted identifiers, `{ElapsedMilliseconds}`, `{ErrorType}`/`{ErrorCode}`; the offenders are the `Key={Value}` probe lines (9116, 9219), `{Detail}` (9125, 9227), the two-sentence warnings (9115, 9216, 9217), `{ElapsedMs}`/`{TookMs}`/`{ProcessingTimeMs}`/`{DelayMs}` names and the `'{StagingIndexName}' was retained …` wording. Categories: every logger is `ILogger<KernelType>`; `MeilisearchServiceCollectionExtensions` takes `ILogger<MeilisearchClient>` (a third-party category) today and switches to a kernel type. Loggers stay required constructor dependencies (L8). Levels follow L6 (per-operation success Debug, lifecycle Information, expected failure Warning, unexpected exception Error; Phase 1 already decided that rethrown exceptions are not logged here).

*Exceptions (E2, E3).* Startup misconfiguration exceptions (`ElasticSearchBuilder`, `MeilisearchSearchBuilder`: `Failed to build the SearchIndexDefinition … {definitionResult.Error.Message}`, and the registration-order messages) are rewritten to the E3 phrasing: sentence, quoted values, name the remedy, the nested `Error.Code` instead of its text. `ArgumentException` from `SearchFilter.Between` and the `ThrowIf*` guards stay (E2).
