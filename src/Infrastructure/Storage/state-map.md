### SK.08.StorageExceptionEdge — Make StorageException map at the edge `○`

**Work order:** WO-087 / P-589 · **Depends on:** SK.01.ObservabilityHelpers (P-580; `IHasError` is satisfied by `SharedKernelException`, no storage code waits on it)

`StorageException` (thrown only by `IFileStorage.ListAsync`, which has no `Result` to return) carries an `Error` but derives `Exception`, so the three edge mappers (`SharedKernelExceptionHandler`, `GrpcExceptionInterceptor`, `HubExceptionMappingFilter`, each switching on `SharedKernelException`) answer 500 and drop the storage code. The phase makes it a sealed `SharedKernelException` (rule E1) with the ctor pair `(Error)` and `(Error, Exception)`, so an outage during enumeration is 503 `storage.unavailable`, a denied listing 403, and so on, from the same `Error.Type` that the `Result` path already maps. It also settles the provider-detail audit (rule 5): reading `StorageErrors` shows every factory builds messages from the store name and the caller's key only; the S3 log statements carry store, bucket, status, S3 error code and request id but no endpoint or URL; one leak exists, `ObsStorageOptionsValidator` quotes `endpoint.Host` in a start-up validation failure, and the phase removes it. A second defect is probed and fixed if it reproduces: a tenant view's `ListAsync` re-yields the inner stream and lets an inner `StorageException` through unrewritten, so a key quoted in its message could show the `tenants/{id}/` prefix (rule 2).

**Behaviour per provider.** None changes: the exception type and its base class are provider-neutral (Abstractions); AWS S3, MinIO and OBS all raise it through the same `ListCoreAsync` path, and `InMemoryFileStorage` mirrors it. No `S3Compatibility` flag, no new verb. **Streaming:** untouched (maximum in-memory footprint unchanged: one multipart part).

**Wire/ABI effect (pre-GA, listed under "Breaking changes" in the PR body):** `StorageException` base type `Exception` to `SharedKernelException`; the single ctor `(Error, Exception? = null)` is replaced by the two explicit ctors (binary break only; source-compatible). Message, `Error` property and codes are unchanged.

### SK.08.StorageConformance — Conform Storage to the gold standard `○`

**Work order:** WO-087 / P-606 · **Depends on:** SK.08.StorageExceptionEdge (P-589), SK.01.ObservabilityHelpers (P-580), SK.16.TelemetryCapture (P-581), SK.13.WildcardTelemetry (P-583 consumers: `WithStorageTelemetry()` is deleted there), SK.00.ObservabilityReportOnly (P-583)

Applies L1-L8, T1-T8, E1-E4 and C1-C3 of root `CLAUDE.md` "Observability, exceptions and error codes" to the three packages, keeping what the audit found right (source and meter already named `SharedKernel.Storage`, span kind Client, `{capability} {operation}` span names, duration in seconds, no object key on spans or metrics, `[LoggerMessage]` only, EventIds in the 8100-8199 sub-block, public `StorageErrorCodes` with lowercase `storage.{reason}` codes, `Result` for expected failures). Measured gaps: (1) `StorageTelemetry` is a static class with hand-read assembly version and a hand-written failure path: the span's `error.type` carries the storage code (T5 wants the `ErrorType` name, with the code in `error.code`), no `outcome` tag exists, an unexpected exception or a cancellation skips `Complete` (no duration, no status, no exception event), and the instruments are `storage.client.operation.duration` and `storage.client.bytes` instead of `sharedkernel.storage.*`; the names are private constants in the S3 package, so the source name is not a public constant and a second provider could not reuse it (T1); the `Meter` is created with `new`, not `IMeterFactory` (T1). (2) `S3StorageLog` uses `LoggingEventIdRanges.Storage + n` arithmetic in the class instead of one `S3StorageLoggingEventIds` (L1), sits in `Internal/` (L2 wants `Diagnostics/`), passes the exception second instead of last (L4), and its templates are colon/parenthetical fragments with unquoted identifiers (L3). (3) `StorageErrors` is public (providers and doubles in other assemblies build errors through it; C2 asks for an internal factory) and timeouts map to `storage.unavailable` (C3 asks for `Timeout`): both are ratified as recorded deviations or changed in D-05. (4) Exception messages in the registry, builder and options validators need the E3 sweep. **Maximum in-memory footprint and streaming rules are unchanged** (rules 6 and 7): no code path of this phase reads a stream.

**Target telemetry contract** (public constants, wire names, pinned literally by tests):
- `StorageTelemetryNames.SourceName = MeterName = "SharedKernel.Storage"`, and `StorageTagKeys` (`storage.store`, `storage.operation`, `storage.provider`, `storage.direction`), both public in Abstractions (neutral, so a future Azure/GCS provider reuses them; no new dependency).
- Spans `storage {operation}`, kind Client, tags store/operation/provider; failure through `RecordResult` (Result failures: status Error, `error.code` = `storage.*`, `error.type` = `ErrorType` name) and `RecordException` (unexpected exceptions: full exception event, rethrown unchanged; `OperationCanceledException` never an error).
- Instruments: histogram `sharedkernel.storage.operation.duration` unit `s`, tags `storage.store`, `storage.operation`, `storage.provider`, `outcome` (`WellKnownOutcomes`), plus `error.type` and `error.code` on failures only (13 bounded codes); counter `sharedkernel.storage.bytes` unit `By`, tags store, provider, direction (unchanged tags).
- Created through `IMeterFactory`; `ActivitySource` static; version from `TelemetryVersion.Of`.

**Breaking changes for the release notes (all pre-GA, no aliases):** instrument `storage.client.operation.duration` renamed `sharedkernel.storage.operation.duration`; `storage.client.bytes` renamed `sharedkernel.storage.bytes`; span/metric tag `error.type` changes meaning from the storage code to the `ErrorType` name, the code moves to `error.code`; new `outcome` tag; `WithStorageTelemetry()` removed (13.ServiceDefaults, wildcard subscription replaces it); log message templates reworded and the exception parameter moved last (EventIds 8100-8105 keep their numbers); new public `StorageTelemetryNames` and `StorageTagKeys`. No error code string changes (D-05 may add none).

**Provider matrix of new behaviour:** telemetry, log shape and exception messages are provider-neutral and identical for AWS S3, MinIO and OBS (OBS logs and emits through the S3 package; the OBS package keeps only `AddObs`, options and the profile). No `S3Compatibility` flag involved. Presigning, tenancy, probes and the key-leak rules (5, 9) are untouched.
