### SK.19.SchedulerLogContext — Log inside the caller scope, no messages in spans or logs `○`

**Work order:** WO-087 / P-598 · **Depends on:** SK.01.ObservabilityHelpers (P-580: `ActivityFailureExtensions`), SK.16.TelemetryCapture (P-581: the WO-087 header requires every Phase 1 test to assert through the capture helpers, so it is a dependency even though the P-entry lists only P-580)

Fixes the two defects the audit found in `SchedulingHostedService`. (1) Ordering: `ExecuteOneAsync` logs `JobFireStarted` (19003), `LockAcquired` (19012), `LockAcquisitionFailed` (19011) and `LockStoreUnavailable` (19016) before `RequestContextScope.Begin` runs (it sits after the lease claim), and `JobCancelled` (19014) and `JobFireThrew` (19006) in catch blocks after the scope was disposed, so the logs most useful for diagnosing a failed fire carry no tenant, actor or correlation id. The loop-level logs (start, stop, faulted, drain timeout, misfire and overlap decisions) run with no ambient context at all. (2) Leaks: `JobFireFailed` (19005) formats `Error.Message` as `{ErrorMessage}` and the span status uses `result.Error.Message` and `ex.Message`, which may carry provider text, hosts or tenant ids. All internal; no public API changes, no wire change except span status text. Template wording, levels, metrics and outcome vocabulary stay for `SK.19.SchedulingConformance` (the existing outcome string literals are deliberately untouched here so they are not edited twice).

### SK.19.SchedulingConformance — Conform Scheduling to the observability gold standard `○`

**Work order:** WO-087 / P-616 · **Depends on:** SK.19.SchedulerLogContext (P-598), SK.01.ObservabilityHelpers (P-580), SK.16.TelemetryCapture (P-581), SK.00.ObservabilityReportOnly (P-583); coordinates with SK.13.WildcardTelemetry (P-582, deletes `WithSchedulingTelemetry`, no ordering needed because the source and meter name `SharedKernel.Scheduling` is kept)

Applies every applicable rule of root `CLAUDE.md` "Observability, exceptions and error codes" to the one package. **Verdict: accept, reshaped in one place.** The P-entry asks for a public `SchedulingErrorCodes`; C2 applies to a capability that produces `Error` values, and this package mints none (a fire's `Result` belongs to the command, the claim outage carries the caching exception's code, registration mistakes are `ArgumentException` per E2), so an empty or invented code class would only be dead API. Declined as a class; recorded in `## Decisions` of `CLAUDE.md` so it does not come back (the caller may override). Not applicable: T7 (no client-facing errors), T8 (the ambient scope already propagates through `RequestContextPropagation` in downstream adapters), E1 (no exception types), C1 and C3 (no codes), L8 (loggers are already required constructor dependencies), L7 (`ILogger<ScheduledCommandJob<TCommand>>` is already compliant because `Logger<T>` drops generic arguments from the category, so no consumer type enters it; pinned by T-04 rather than changed).

**Final instrument set** (T6; every name `sharedkernel.scheduling.*`, tag `scheduling.job_name` on all, `outcome` where stated):

**Span** (T3, T4, T5): name `scheduling fire` (was `Scheduling.Job.Fire`), kind `Internal`, tags `scheduling.job_name`, `scheduling.misfire_policy`, `scheduling.overlap_policy`, `outcome` (the shared four-value vocabulary, taken from the recorder's return value, set only when the command was attempted or an exception occurred) and the new package tag `scheduling.claim` = `acquired`/`not_acquired`/`store_unavailable` (absent with no lock service). The old `scheduling.outcome` key and the strings `succeeded`/`failed`/`threw`/`cancelled`/`lock-not-acquired`/`lock-store-unavailable` disappear; a lost claim sets `scheduling.claim` and no `outcome`, a lock outage records the exception (`outcome` = `exception`).

**Log templates** (L3, L6; drafts the implementer may refine within the rule, the P-581/P-583 checks enforce it): 19000 `Scheduling started with {RegisteredJobCount} registered jobs.`; 19001 `Scheduling is stopping.`; 19002 `No IDistributedLockService is registered, so every job runs once per replica; register one before running more than one replica.`; 19003 `Job '{JobName}' is firing the occurrence scheduled at {ScheduledFireTimeUtc}, observed at {ActualFireTimeUtc}.`; 19004 Debug `Job '{JobName}' running '{RequestType}' succeeded in {ElapsedMilliseconds} ms.` (`{RequestType}` is `typeof(TCommand).FullName`, matching the pipeline; was `{CommandType}` short name); 19005 Warning `Job '{JobName}' running '{RequestType}' failed in {ElapsedMilliseconds} ms with {ErrorType} '{ErrorCode}'.`; 19007 and 19010 raised to Warning (an occurrence that never runs); 19016 and the rest rewritten without em-dashes, parentheticals or capitals. New 19017 `ShutdownDrainFaulted` (Error, passes the exception) replaces the silent `catch (Exception)` in `StopAsync` (E4: a swallowed failure becomes a diagnosable one; the boundary catches in `ExecuteOneAsync` and the loop stay, ratified as job-isolation boundaries that log, record and, for the loop, rethrow).
