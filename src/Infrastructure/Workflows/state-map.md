### SK.17.WorkflowObservabilityFixes — Make Workflows observable and stop its leaks `○`

**Work order:** WO-087 / P-597 · **Depends on:** SK.01.ObservabilityHelpers (P-580), SK.16.TelemetryCapture (P-581), SK.13.WildcardTelemetry (P-582)

Fixes the Workflows defects of the WO-087 audit and nothing else; shape and naming conformance is `SK.17.WorkflowConformance`. (1) `WorkflowDiagnostics.ActivitySource` is never started (rule 5 forbids `Activity` use in workflow code and the dispatcher relies on Temporal's `TracingInterceptor`), so `WorkflowWellKnown.ActivitySourceName` and the source go; spans come from the `TracingInterceptor` sources that `13.ServiceDefaults` subscribes (P-582), and this phase proves a start, a workflow and an activity span appear and carry no tenant, business key or workflow id. The `SharedKernel.Workflows` **meter** stays: it is the sink `WithMetrics()` hands to the SDK's `CustomMetricMeter`, so it is not dead. (2) The workflow id is `{tenant}:{type}:{businessKey}` (`WorkflowIdFactory`), so logging it, or putting it in a message, leaks tenant and business key; logs carry `WorkflowType`, `TaskQueue` and signal/query names only, and `Error.Message` text stops embedding ids and raw `RpcException`/exception text (`ExtractWorkflowId` returns `exception.Message` today). (3) The readiness probe swallows both fault catches silently; each logs the exception through a new event 17013. (4) `WorkflowFailureMapper` maps every `RpcException` to `service_unavailable`, so `not_found`, `namespace_not_found` and timeouts are never produced; it maps by status instead, and `TimedOut`/`ServiceUnavailable` become `Timeout`/`Unavailable` (no rule-8 row flips: `Unexpected`, `Unavailable` and `Timeout` are all retryable in `ToFailure`, and `ErrorType` numbering is untouched). (5) The builder passes a reason sentence into `WorkerNotConfigured(taskQueue)`; the site gets a correct message. Wire-visible changes (public API, codes, messages) are listed under Breaking changes below.

**Design (file-level), all in `SharedKernel.Workflows.Temporal`:**
- `Diagnostics/WorkflowDiagnostics.cs`: `Meter` only, constructed with `TelemetryVersion.Of(typeof(WorkflowDiagnostics).Assembly)`; `Constants/WorkflowWellKnown.cs`: `ActivitySourceName` removed, `MeterName` kept.
- `Hosting/TemporalWorkflowsBuilder.cs`: `TracingInterceptor` options per D-02; `Build()` task-queue message fixed.
- `Logging/WorkflowLog.cs`: `workflowId` parameter removed from 17000, 17002, 17003, 17004, 17005 (call sites in `WorkflowDispatcher` and `WorkflowPropagationInterceptor`); new `ProbeCheckFailed(logger, check, exception)` = 17013 Warning, declared through a new internal `WorkflowLoggingEventIds` class (`Base = LoggingEventIdRanges.Workflows`, no bare literal for new code; `SK.17.WorkflowConformance` moves the existing 13 into it).
- `Health/WorkflowServiceProbe.cs`: both catches log 17013 with the exception (`check` = `reachability` / `namespace`); the cancellation filter stays.
- `Errors/WorkflowErrors.cs`: `TimedOut` → `Error.Timeout`, `ServiceUnavailable` → `Error.Unavailable`; `NotFound`, `AlreadyStarted`, `Cancelled`, `Terminated`, `TimedOut`, `ServiceUnavailable` lose their id/reason parameters (fixed sentences); new `RequestTimedOut()` (`workflow.request_timed_out`, `Timeout`) and `RpcFailed()` (`workflow.rpc_failed`, `Unexpected`).
- `Failures/WorkflowFailureMapper.cs`: `ToError` RPC arm maps by status (table in D-01); `ExtractWorkflowId` deleted; the `unmapped_failure` arm and the RPC arms carry fixed messages.
- `SharedKernel.Workflows.Testing`: `InMemoryWorkflowDispatcher`, `InMemoryWorkflowHandle`, `InMemoryWorkflowHandle<TResult>` and their self-tests follow the factory signatures and types.

**Breaking changes (release notes):** `WorkflowWellKnown.ActivitySourceName` removed (no `SharedKernel.Workflows` source ever emitted); `WorkflowErrors.NotFound/AlreadyStarted/Cancelled/Terminated/TimedOut/ServiceUnavailable` lose their string parameter; `workflow.timed_out` is now `Timeout` and `workflow.service_unavailable` now `Unavailable` (edge status codes change, `14.Presentation` maps by `ErrorType`); new codes `workflow.request_timed_out`, `workflow.rpc_failed`; `Error.Message` of every dispatch error no longer contains an id or exception text; log templates 17000/17002/17003/17004/17005 lose `{WorkflowId}`.

### SK.17.WorkflowConformance — Conform Workflows to the gold standard `○`

**Work order:** WO-087 / P-614 · **Depends on:** SK.17.WorkflowObservabilityFixes (P-597), SK.01.ObservabilityHelpers (P-580), SK.16.TelemetryCapture (P-581), SK.00.ObservabilityReportOnly (P-583)

Applies every applicable rule of root "Observability, exceptions and error codes" to the package after Phase 1. **C1/C2:** public `WorkflowErrorCodes` (none exists; the codes live as `$"{Prefix}.x"` interpolations in `WorkflowErrors`, and the mapper holds raw `"workflow.application_failure"` and `"workflow.unmapped_failure"` literals, SK0022); `WorkflowErrors` becomes the internal factory. **E1/E3:** the `InvalidOperationException(error.Message)` sites are the six in `TemporalWorkflowsBuilder` (`WithWorker` twice-call, no task queue, empty worker, workflow registration, `TargetHost`, `Namespace`; the audit counted nine, the on-disk count at b7daa29c is six plus the two in `EncryptionPayloadCodec`, and the plain `InvalidOperationException`s that wrap no `Error` stay). The codec pair becomes a classified `WorkflowPayloadCodecException : SharedKernelException` (`(Error)` and `(Error, Exception)`, `workflow.payload_codec_failure`, no cipher or key detail in the message) logged as 17006 before the throw; the builder sites are composition errors that must fail at `Build()` and never reach an edge, so they stay `InvalidOperationException` with sentence messages that name the remedy (E2; this reads the brief's "classified exceptions" as the codec only, to be confirmed in D-03). **E4:** the dispatcher, handle adapter and `DescribeAsync` catch `Exception` and turn anything into a `Result`, hiding programming defects; they catch only `TemporalException` and let the rest propagate, and the mapper's `catch (Exception)` decode becomes a typed read. **One dispatch mechanism:** `GetHandle` throws `ArgumentException` for `Global` and blank ids while `StartAsync`/`DescribeAsync` return `Result`; both `GetHandle` overloads return `Result<IWorkflowHandle>`/`Result<IWorkflowHandle<TResult>>` through one shared guard. That guard also closes a gap found while planning: `GetHandle` and `DescribeAsync` accept a composed id and never check it belongs to the caller's tenant (rule 13 only governs starts), so a tenant can attach to another tenant's id; the guard refuses a foreign id with `workflow.not_found` (no existence oracle). **L1-L8:** `WorkflowLoggingEventIds` holds all 14 events (values 17000-17013 unchanged), `WorkflowLog` moves to `Diagnostics/`, templates follow L3, levels follow L6 (17000 per-operation success becomes `Debug`), the four never-called events 17002/17003/17004/17006 are wired and dispatch failures are logged (new 17014 `Warning` with `{Operation}`, `{ErrorType}`, `{ErrorCode}`; new 17015 `Error` with the exception for a `TemporalException` the mapper has no row for); `ActivityBase` keeps the consumer's `ILogger` category deliberately (activity logs are the consumer's own, recorded in Decisions). **T1:** the meter comes from `IMeterFactory`. **T3-T8:** no kernel spans (Decisions), no edge, propagation already through `RequestContextPropagation`.

**Breaking changes (release notes):** `IWorkflowDispatcher.GetHandle` and `GetHandle<TResult>` return `Result<…>` (and refuse a foreign tenant's id); `WorkflowErrors` is no longer public, callers compare `WorkflowErrorCodes`; removed codes and factories per D-02; the codec failure is `WorkflowPayloadCodecException` instead of `InvalidOperationException`; builder messages reworded; `InMemoryWorkflowDispatcher` follows; log templates reworded (EventIds unchanged); the `ReadOriginalErrorType`/dispatch catch narrowing means a non-Temporal exception now propagates instead of becoming `workflow.unmapped_failure`.
