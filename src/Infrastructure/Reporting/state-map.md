## Open Work

### SK.20.ReportingErrorShape — No provider detail in errors, classified abort exception `○`

**Work order:** WO-087 / P-599 · **Depends on:** SK.01.ObservabilityHelpers (P-580: `IHasError` on `SharedKernelException`; the exception itself already exists in `SharedKernel.Core`)

Fixes the two Phase 1 defects in Reporting. (1) `GotenbergHtmlToPdfConverter` builds `Error` messages from the Gotenberg host (`client.BaseAddress`, three sites) and from the response body (`ReadErrorAsync`, three sites), and `ConverterUnavailable`/`ConversionFailed` take a free `reason` string for exactly that, so a base URL, an internal route or arbitrary engine output reaches `Result` consumers and, through ProblemDetails, API clients (E3, L5). Every Gotenberg `Error` becomes a fixed sentence per code with no host, route, credential hint, status text or body; the detail an operator needs (the HTTP status code, the `HttpRequestError` enum) moves to two new log records in the `.Gotenberg` sub-block, which are written to the gold standard from the start (new code is binding now). (2) `ReportAbortedException` (internal, in `ReportingDependencies.cs`) is built from an error-code string and carries no `Error`, so it would map to 500 at every edge that sees it; it becomes a sealed `SharedKernelException` carrying the writer's own `Error` unchanged. Today it never leaves `StoreCoreAsync` (it faults the pipe; when the encode failed the method returns the writer's `Error` before the upload task is awaited), but the storage provider reading the faulted pipe records it on its own span and logs, and `IHasError` lets that span carry the cause `error.code`. **Stored/wire formats:** none. **Breaking (for the release notes):** `ReportingErrors.ConverterUnavailable(string)` and `ConversionFailed(string)` lose their `reason` parameter; the messages of `reporting.converter_unavailable`, `reporting.conversion_failed` change; `SharedKernel.Reporting.Abstractions` gains a `SharedKernel.Core` dependency (Foundation to Abstractions, legal; additive `.nuspec` entry).

**Message table (D-01).** The code and `ErrorType` of every mapping rule (rule 11) are unchanged; only the text changes.

| Condition | Code (`ErrorType`) | Message |
| --- | --- | --- |
| 4xx other than 401/403/404/408/429 | `reporting.conversion_failed` (`Validation`) | The document could not be converted. |
| 401, 403, 404, 429, 5xx, unreachable | `reporting.converter_unavailable` (`Unavailable`) | The document converter is unavailable. |
| 408, 504, timeout | `reporting.conversion_timeout` (`Timeout`) | The document conversion did not finish within {timeout}. (unchanged; the configured timeout is not a host) |

### SK.20.ReportingConformance — Reporting conforms to the observability gold standard `○`

**Work order:** WO-087 / P-617 · **Depends on:** SK.20.ReportingErrorShape (P-599), SK.01.ObservabilityHelpers (P-580), SK.16.TelemetryCapture (P-581), SK.13.WildcardTelemetry (P-582), SK.00.ObservabilityReportOnly (P-583)

Brings every Reporting package to root `CLAUDE.md` "Observability, exceptions and error codes" (L1-L8, T1-T8, E1-E4, C1-C3), keeping what the audit found right: span names `reporting export`/`reporting convert`, the `reporting.format`/`operation`/`store`/`row_count`/`size_bytes` tag values, the unit `s` on the duration histogram, no row content or object key anywhere, one source and one meter named `SharedKernel.Reporting`. Concrete defects fixed: `ReportingTelemetry.Failed` writes `Error.Code` into `error.type` and the status description (T5), cancellation is marked as an error with `error.type = "cancelled"` (T5, T6), instrument names lack the `sharedkernel.` prefix and the metric has no `outcome` tag (T6), the meter and version are hand-built and not from `IMeterFactory`/`TelemetryVersion` (T1), tag keys are bare constants in the telemetry class (T4), the seven log templates are free-form (`Report {Operation} completed: format {Format}, ...`), `{DurationMs}` is non-standard, two success records log at Information, the category is a hand-typed string and the logger is optional (L3, L6, L7, L8), the correlation header is written by hand (T8), one `InvalidOperationException(error.Message)` site (E3), and `unsupported_format` is the odd word out of the C3 vocabulary. The audit named `*.client.operation.duration`; Reporting's instruments never had `client` in the name, the rename here is the `sharedkernel.` prefix. **Stored/wire formats:** none touched; metric, tag and code names are dashboard-visible and pinned literally.

**Telemetry (D-01).** Final names, so no later rename:

| Instrument | Type, unit | Tags | When |
| --- | --- | --- | --- |
| `sharedkernel.reporting.operation.duration` (was `reporting.operation.duration`) | Histogram, `s` | `reporting.format`, `reporting.operation`, `outcome`, plus `error.type` on `failure`/`exception` | every call, including pre-I/O validation failures |
| `sharedkernel.reporting.rows` (was `reporting.rows`) | Counter, `{row}` | `reporting.format` | success only |
| `sharedkernel.reporting.bytes` (was `reporting.bytes`) | Counter, `By` | `reporting.format`, `reporting.operation` | success only |

Spans keep their names and `Internal` kind (the storage upload is the Client child). Failure recording only through the P-580 recorder: Result failure `RecordResult`/`RecordFailure` (status description = `Error.Code`, `error.code` = `Error.Code`, `error.type` = `ErrorType`), exception `RecordException` (full exception event, `error.type` = exception full name), cancellation status Unset with outcome `canceled`; the returned outcome string is the metric's `outcome` tag. The metric's `error.type` is bounded (enum name or CLR type), never `error.code`. `ReportingDiagnostics` (new, `public static`, namespace `SharedKernel.Reporting`) exposes `ActivitySourceName` and `MeterName` = `SharedKernel.Reporting` (the shape `SK.16.TelemetryCapture` uses). The `ActivitySource` stays static and is created with `TelemetryVersion.Of(typeof(…).Assembly)`; the `Meter` comes from an optional `IMeterFactory` with `MeterOptions` carrying the same version, falling back to a directly created `Meter` when none is registered (`AddMetrics()` lives in `Microsoft.Extensions.Diagnostics`, not an `.Abstractions` package, so `AddSharedKernelReporting()` cannot register it at this tier; hosts built with the Host builders already have it).

**Error codes (D-02).** All eight codes reviewed against C1-C3; one rename, `reporting.unsupported_format` to `reporting.format_not_supported` (`Validation`; `not_supported` is the C3 reason word, same rename family as `search.not_supported` and `intelligence.not_supported`). Codes and `ErrorType`s otherwise unchanged and pinned in one table test. `ReportingErrorCodes` is already public with XML docs and stays. `ReportingErrors` stays a public class (C2 wants an internal factory; a class cannot be half public) but its members follow the planner precedent "public only when a sibling assembly constructs it": public `RowLimitExceeded` (Spreadsheet, Pdf), `ConversionFailed`, `ConverterUnavailable`, `ConversionTimeout` (Gotenberg), `InvalidDestination` and `FormatNotSupported` (the `.Testing` doubles); `InvalidDefinition` and `InvalidRequest` become `internal` (only `.Abstractions` builds them; `PublicAPI.Unshipped.txt` lines removed). Messages reviewed for E3 (sentence, period, quoted values, "must not").

**Exceptions (D-03).** The one `throw new InvalidOperationException(invalid.Error.Message)` (`ReportDefinitionBuilder.Build`) becomes a new public sealed `InvalidReportDefinitionException : SharedKernelException`, ctors `(Error)` and `(Error, Exception)`, carrying `reporting.invalid_definition` (`Validation`). Why classified rather than E2: columns are often chosen at runtime (a user-picked column list), the same condition already returns `reporting.invalid_definition` as a `Validation` `Result` from `ExportAsync`, and the edge then answers 400 instead of 500. Rejected: keep `InvalidOperationException` with a hand-written message (loses the code at the edge). Breaking: callers that catch `InvalidOperationException` around `Build()`. The remaining `InvalidOperationException` sites are E2 configuration errors and stay, with E3 wording and no embedded rule text: missing storage registration (`ReportingDependencies`), unregistered format (`ReportExporterFactory.GetExporter`, "No report exporter is registered for the format '{x}'. Registered formats: …. Call AddCsv, AddSpreadsheet or AddPdf on AddSharedKernelReporting()."), duplicate `AddExporter` ("… must not also use …", not "cannot"), the missing embedded font resource. `InMemoryReportExporterFactory.GetExporter` mirrors the real wording.

**Logging (D-04).** `ReportingLoggingEventIds` (internal, `Base = LoggingEventIdRanges.Reporting`, constants `Base + n`) replaces the seven bare `LoggingEventIdRanges.Reporting + n` expressions; ids 20000-20006 are not renumbered. Sub-blocks stay as recorded (Abstractions 20000, Csv 20100, Spreadsheet 20200, Pdf 20300, Gotenberg 20400); Csv, Spreadsheet and Pdf log nothing and keep their blocks reserved (no empty classes). Templates become sentences with a trailing period and quoted identifiers: `Report {Operation} for format '{Format}' started.`, completed `…produced {RowCount} rows and {SizeBytes} bytes in {ElapsedMilliseconds} ms.`, failed `…failed with error code '{ErrorCode}'.` (adds `{ErrorType}`), threw, cancelled, presign failed `…the download link could not be created for store '{Store}' (error code '{ErrorCode}').` reworded to one sentence, converted. Levels per L6: `Completed` and `Converted` Information to Debug (per-operation success), the rest unchanged. Category `ILogger<ReportingDependencies>` replaces `CreateLogger("SharedKernel.Reporting")` and `ReportingLog.CategoryName` goes (category string changes to `SharedKernel.Reporting.ReportingDependencies`: a breaking filter-rule change for consumers). The `ReportingDependencies` ctor takes a required `ILogger<ReportingDependencies>` (L8), an optional `IFileStorageFactory?` and an optional `IMeterFactory?`; the `"(stream)"` literal becomes a named constant.

**Propagation (D-05).** `GotenbergHtmlToPdfConverter` writes the correlation id through `RequestContextPropagation.WriteHeaders` called with a `null` context and the explicit `CorrelationIds.Current(requestContext?.Current)`; the setter maps `WellKnownHeaders.CorrelationId` to the vendor header `Gotenberg-Trace` (the only header Gotenberg correlates its own logs with; the named constant stays, rule 11). Same shape 15.Integration plans for webhooks: no tenant, actor or client header ever leaves the platform towards the sidecar (it is a third-party process and a Chromium that renders caller-supplied HTML), and the hand-rolled `TryAddWithoutValidation` goes, so the id passes the shared helper's validation. Root `CLAUDE.md` "Propagating context on outbound calls" does not list Reporting, so no correction is needed for this domain.
