## Open Work

### SK.13.WildcardTelemetry — Wildcard subscription and one resource in `AddServiceDefaults` `○`

**Work order:** WO-087 / P-582 · **Depends on:** SK.01.ObservabilityHelpers (P-580, for `TelemetryVersion.Of`)

`AddSharedKernelTelemetry()` (so `AddServiceDefaults()`) subscribes every `SharedKernel.*` `ActivitySource` and `Meter` by wildcard, so a capability's telemetry can never again be dropped by a hand-copied name (the Messaging meter `SharedKernel.Messaging` and the Temporal sources are dropped today; Integration, Storage and others are dropped in any host that forgets the matching call). The per-capability `With{X}Telemetry()` family shrinks to the four that wire **third-party** instrumentation: `WithMessagingTelemetry` (`MassTransit` source and meter), `WithPersistenceTelemetry` (`Npgsql` source and meter), `WithCommunicationTelemetry` (gRPC client instrumentation, `Polly` meter) and `WithWorkflowTelemetry` (the `Temporalio.*` sources of the Temporal tracing interceptor). The other eight (`Application`, `Caching`, `Integration`, `Intelligence`, `Reporting`, `Scheduling`, `Search`, `Storage`) wire only kernel names and are **deleted** (pre-GA breaking change, WO-087 decision 2). The base also gains HttpClient metrics and the framework SignalR server sources, and `service.version` becomes the entry assembly's informational version through `TelemetryVersion.Of`, with a single resource configuration instead of today's three `SetResourceBuilder` calls plus a `ConfigureResource`. The base keeps referencing `SharedKernel.Primitives` and OpenTelemetry only (rule 1); nothing is created on another domain's behalf. This phase does not change any source, meter or instrument name, so every owning domain's renames and the Persistence meter consolidation need no coordination here.

**Design (file-level).** All in `SharedKernel.ServiceDefaults/Telemetry/`:
- `TelemetryExtensions.AddSharedKernelTelemetry`: one `ConfigureResource(r => r.AddService(serviceName, serviceVersion: resolved))`; the three `SetResourceBuilder(resourceBuilder)` calls and the local `ResourceBuilder` go. `serviceVersion` comes from an internal `ResolveServiceVersion(Assembly? entry)` = `entry is null ? TelemetryVersion.Unknown : TelemetryVersion.Of(entry)` (`TelemetryVersion.Of` throws on null by its contract). Tracing adds `AddSource(TelemetryNames.SharedKernelWildcard)` plus the SignalR server sources; metrics add `AddMeter(TelemetryNames.SharedKernelWildcard)`, `AddHttpClientInstrumentation()` and the duration view.
- New internal `TelemetryNames` holds `SharedKernelWildcard = "SharedKernel.*"` and the framework source names (SK0022: one declaration, used by the code only).
- Duration view: one `AddView(Func<Instrument, MetricStreamConfiguration?>)` for `Histogram<double>` instruments of meters named `SharedKernel.*` with unit `s`, applying the semantic-convention second-scale boundaries now hard-wired for `sharedkernel.application.request.duration`. It replaces `ApplicationTelemetryExtensions`' name-based view and its marker guard, and also covers every other domain's second-unit histogram (audit T6) without a per-instrument edit.
- Kept extensions lose every `SharedKernel.`-named literal: `WithMessagingTelemetry` = `MassTransit` source and meter; `WithPersistenceTelemetry` = `Npgsql` source and meter; `WithCommunicationTelemetry` unchanged in behaviour; `WithWorkflowTelemetry` = the Temporal sources (`SharedKernel.Workflows` is dead and covered by the wildcard anyway).

### SK.13.HostObservabilityFixes — Server-span tags, request-context header read, safe host logs `○`

**Work order:** WO-087 / P-594 · **Depends on:** SK.01.ObservabilityHelpers (P-580, conventions only: nothing from it is called here), SK.13.WildcardTelemetry (P-582, ordering only: same test projects, no shared code), SK.16.TelemetryCapture (P-581, for the assertions; see Blocked)

Phase 1 of WO-087 for this domain: the six defects the audit verified, nothing else (the structural clean-up is `SK.13.ServiceDefaultsConformance`). **Verdict: accept, with one reshape.** The reshape is the header read (D-03): the host now reads the request-context headers through `RequestContextPropagation.ReadHeaders`, but the parsed actor, client and tenant are **never applied** to `IRequestContext` and never tagged, because an inbound HTTP header is forgeable by any external caller (rules 9, 10, 11, 19) and traces share the trust level of logs (WO-087 decision 4). What changes:

1. **Server span tags.** The ASP.NET Core server span (`Activity.Current` while `UseSharedKernelRequestContext()` runs, because it is the first middleware) gets `correlation.id` from `RequestContextMiddleware` and `tenant.id` from `TenantResolutionMiddleware`, both through `WellKnownTagKeys`. Today both ids exist only as baggage (`RequestContextMiddleware.cs:63`, `TenantResolutionMiddleware.cs:133-140`), so a trace backend cannot search by them. This domain starts no span and owns no `ActivitySource`: it tags the ambient one. The tags are written before `UseExceptionHandler()` runs, so a handled exception cannot remove them (the coordination point with `14.Presentation`, see Cross-Domain Dependencies).
2. **Header read.** `RequestContextMiddleware` replaces its hand-rolled `Headers[WellKnownHeaders.CorrelationId]` + `CorrelationIds.IsValid` with one `RequestContextPropagation.ReadHeaders(request.Headers, …, createCorrelationId: false)` call (T7/T8). The correlation id is taken from the result; when it is `null` the raw header's presence and length still select 13006 (absent) or 13007 (rejected, length only; rule 8).
3. **mTLS logs.** `MtlsLog` stops writing the certificate subject (distinguished name, personal and organisational data) and the remote IP; the forwarded-header refusal stops reusing 13001 with `(not decoded)` placeholders and gets its own message (**13008**, next free in the shared range, no parameters; the whole range is re-blocked by `SK.13.ServiceDefaultsConformance`, which renumbers it in the same release, so this id never ships). The free-text `{Reason}` goes too (the validator's `FailureReason` is caller-supplied text).
4. **Multi-tenancy log.** `MultiTenancyLog.TenantResolved` (13100) drops the `{TenantId}` placeholder and its documented exemption; the tenant still reaches the exported log record through the baggage processor.
5. **Readiness probe log.** `ReadinessProbeThrew` (13005) passes the `Exception` (last parameter) instead of `exception.GetType().Name`; the `/health/ready` body keeps showing the type name only.

The `Next free` EventId is 13009 after this phase. No public API changes (every touched member is internal); no `.Testing` double changes (`FakeTenantResolutionStrategy`, `InMemoryTenantCatalog`, `HealthCheckAssertionExtensions` do not touch the changed members; verify when implementing).
