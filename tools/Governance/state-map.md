### SK.00.ServiceShapeRules — Ship the service-shape and placement rules and the embedded kernel package index `○`

**Work order:** WO-090 / P-635 · **Depends on:** None

Verdict: accept. The checks of a consuming service's project shape (`samples/Shop/Shop.TestSupport`: `ServiceShape`, `DependencyGraph`, `KernelPackageIndex`) are copied into every generated service and drift. Ship them in `SharedKernel.ArchitectureTests` as additive public API: shape rules for the four-project variant (Domain, Application, Infrastructure, Api/Worker) and the six-project variant (adds Contracts and Client), nine placement rules, and a kernel package-tier index embedded in the assembly and generated by `eng/generate-package-index.cs` from the same inventory as `docs/packages.md`. These do not restate a tier edge (rule 1): they check which tiers each project of a *service* may reach, which the kernel's matrix cannot see. Every rule is opt-in, so a 1.0.0 consumer's tests are unchanged. The package keeps referencing nothing in the kernel and gains no package reference (no FluentAssertions: failures surface as `ArchitectureRuleViolationException`, as `ArchitectureRuleBase` does today).

Where each constraint is enforced: edges between a service's own projects and the tiers each may reach: architecture assertion over the test assembly's `.deps.json` (new `ServiceShapeRules`); type placement, segment and exception bans: rule factories returning `ConditionList` (new `ServicePlacementRules`); the tier of a kernel package: embedded generated data; kernel-internal tier edges: unchanged, MSBuild (SKTIER001-006). No analyzer and no SK id is assigned.
