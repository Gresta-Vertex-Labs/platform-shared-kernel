### SK.00.ObservabilityReportOnly — WO-087 governance rules in report-only mode `○`

**Work order:** WO-087 / P-583 · **Depends on:** P-580 (`SK.01.ObservabilityHelpers`: `IHasError`, `LoggingEventIdRanges` helpers; SK0043's real-type test needs `SharedKernelException : IHasError`)

Ships the checks that will enforce root `CLAUDE.md` "Observability, exceptions and error codes" (G1-G4 plus the log-template and error-code format checks) in a mode that never fails the build or a test, and prints per-domain finding counts so each domain's Phase 1/2 can show its count fall to zero. P-618 then flips **one** property. Nothing here is runtime code and no tier edge changes.

**Where each constraint is enforced** (verdict: accept, reshaped in four places)

| Constraint | Enforced by | Why this shape |
| --- | --- | --- |
| G1 kernel analyzers in `src/` + CA2200 | MSBuild props + a severity `.globalconfig` pair in `tools/Governance/SelfAnalysis/` (no SK id) | A wiring, not a rule. The one-line import into the root build files is devops-lead's (note below). |
| G2 platform-wide EventId ownership | Architecture assertion over built assemblies (Mono.Cecil): one 100-wide sub-block per assembly, no sharing, inside the domain block (no SK id) | Whole-assembly property. |
| G2 "no bare EventId literals" | **Analyzer SK0044** (reshaped from "test") | A `const int` folds into the attribute blob, so IL cannot tell a literal from a named constant; only syntax shape can (rules 9, 14). |
| G3 source/meter names, instrument units | Architecture assertion over IL (no SK id) | Constructor and `Create*` call facts. |
| G3 tag keys not raw literals | **SK0022 gains a fifth shape** (metric tags), no new id (reshaped) | `Activity.SetTag`/`AddTag` is already SK0022 shape 2; only the instrument-tag shapes are missing. A second tag-literal rule would split one rule in two. |
| G4 exception exposing an `Error` must derive `SharedKernelException` | **Analyzer SK0043** | Per-type symbol fact; also helps consumers' own exceptions. |
| Log template; error-code format | Architecture assertions over IL (no SK id) | Message and code strings are readable from attributes and constants; both report every site rather than the first. |

**Ids assigned:** SK0043 `ExceptionExposingErrorMustDeriveSharedKernelException` (Design, Warning, on by default), SK0044 `LoggerMessageEventIdBareLiteral` (Design, Warning, **off by default**, enabled for the kernel by the self-analysis config; ratified in D-02). Anchors `sk0043-exceptionexposingerrormustderivesharedkernelexception`, `sk0044-loggermessageeventidbareliteral`. SK0022 is extended, not re-issued.

**The report switch (P-618 consumes it).** One property, one file: `tools/Governance/SelfAnalysis/ObservabilityMode.props` defines `SharedKernelObservabilityMode` = `report` (the committed default) or `enforce`. It drives both consumers:

- Analyzers: `SharedKernel.SelfAnalysis.props` picks `kernel-report.globalconfig` (SK analyzers and CA2200 at `warning`, and the SK ids in `WarningsNotAsErrors` so projects with `TreatWarningsAsErrors` stay green) or `kernel-enforce.globalconfig` (same ids at `error`).
- Tests: the same property is stamped into the `SharedKernel.ArchitectureTests.Tests` assembly as `AssemblyMetadata("SharedKernelObservabilityMode", …)` and read by `ObservabilityEnforcement.Configured`; `SHAREDKERNEL_OBSERVABILITY_MODE` overrides it for a local experiment.

P-618's flip is: change `report` to `enforce` in that one file (then delete the report plumbing). Every assertion takes the mode as a parameter, so the firing tests already prove the enforce path today.
