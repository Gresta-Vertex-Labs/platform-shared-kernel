As of 2026-07-21 (WO-045, P-279), `10.Intelligence`'s Design phase is fully `●` closed — `10.Intelligence/CLAUDE.md`'s Interface Contracts section is RATIFIED, not a placeholder. Read that file directly for the full member-by-member surface; this memory captures the decisions and reasoning that must not be re-litigated by accident in a future session.

**Package split — Shape C, ratified:** `SharedKernel.AI.Abstractions` + three sibling packages `SharedKernel.AI.Qdrant`, `SharedKernel.AI.Milvus`, `SharedKernel.AI.SemanticKernel`. Matches the `08.Storage`/`09.Search` sibling-provider precedent. Rejected Shape B (`.VectorDb.Qdrant`/`.VectorDb.Milvus`) because the `.{Provider}.{Role}` pattern is reserved for one technology serving multiple roles (`02.Caching` Redis split), not two technologies serving one role. The old `SharedKernel.AI.VectorDb` placeholder is retired (Scaffold task S-01); the stray domain-root `SharedKernel.AI.Tests` is re-homed to `SharedKernel.AI.Abstractions.Tests` (S-02). **A root-brain edit is still outstanding** (Folder Map row 10 + Abstractions table — currently says `.VectorDb`, needs to say `.Qdrant`/`.Milvus`/`.SemanticKernel`) — recorded as a `/sync-brain` obligation, not yet performed.

**`Microsoft.Extensions.AI.Abstractions` — declined for `.Abstractions`.** Every prior `.Abstractions` package in the repo carries zero third-party `PackageReference`s; M.E.AI has no vector-database concept at all (covers at most half this domain); it carries no representation of the domain's sharpest invariant (mandatory model-identity/dimension/metric binding). Provider packages remain free to adopt M.E.AI internally (e.g. `SharedKernel.AI.SemanticKernel` may use SK's own M.E.AI-based connectors under the hood) — the decision is scoped to `.Abstractions` only.

**Key seam-rule adjudications worth remembering for future phases:**

- **No `WriteConsistency`/consistency-level parameter anywhere on the write surface** — this was the domain's sharpest single "one more knob" rejection. Qdrant's `wait` boolean and Milvus's consistency-level-governs-a-subsequent-query model are NOT the same knob in different clothes; a shared enum would be honest on Qdrant and control nothing on Milvus. Solved instead with a separate opt-in `WaitUntilQueryableAsync(receipt, timeout, ct)` barrier, mirroring `09.Search`'s `WaitUntilSearchableAsync`. If a future request proposes any write-time consistency knob, it must be rejected the same way unless it's proven honestly implementable by both engines.
- **`VectorHit.Score` is KEPT** — the one deliberate deviation from `09.Search`'s outright `Score` ban. Rationale: this domain's own phase brief explicitly said similarity score is "often genuinely load-bearing" for RAG callers in a way full-text relevance rarely is. Kept, but with capitalized XML-doc warnings that the scale is provider- and metric-specific, non-portable, never to be persisted/thresholded/compared across a provider or metric swap. `Rank` remains the portable substitute alongside it.
- **`ISemanticKernel` has NO tool-execution, NO retry, NO caching member** — all three are deliberate stateless-boundary omissions. Tool execution is always consumer-owned (the contract only surfaces `ToolCallsRequested` + `ToolCalls`; the caller executes and feeds a `ToolCallResult` back via a follow-up `CompleteAsync`). Retry, if a provider offers it at all, is an explicit bounded opt-in builder call, never reachable through the interface. No caching member exists at all — `10.Intelligence` may not reference `02.Caching`.
- **`IVectorProviderDescriptor` and `ICompletionProviderDescriptor` are deliberately SEPARATE interfaces** — a vector engine's ceilings (batch size, dimension, filter depth) and an LLM's ceilings (context window, max output tokens) share no honestly-common members; forcing them onto one type would itself be a seam violation.
- **`VectorFilter` is a structural twin of `09.Search`'s `SearchFilter`** — same closed 8-node AST (Equal/NotEqual/In/Range/Exists/And/Or/Not), same private-protected-base/internal-subtype-constructor mechanism, reusing a `VectorValue` scalar union that is a structural twin of `SearchValue` (same 5 kinds: String/Int64/Double/Boolean/DateTimeOffset). `Between` rejects String/Boolean bounds on both domains for platform-wide consistency (Qdrant genuinely can't do lexicographic ranges; Milvus could but is deliberately kept symmetric with the Search precedent).
- **`IVectorRecord.ModelId` is carried on the record itself**, not inferred from `Vector.Length` — dimension alone can't distinguish two different models sharing a dimension. This is the direct implementation of the domain's sharpest invariant (model-identity mismatch is undetectable by any engine).
- **`VectorFieldDefinition` has exactly ONE boolean (`Filterable`)** — deliberately fewer than `SearchFieldDefinition`'s four (no Searchable/Sortable/Facetable — none of those concepts exist honestly on vector-DB metadata). This is the surface to guard hardest; any future added boolean is very likely a claim about one engine that's a lie about the other.
