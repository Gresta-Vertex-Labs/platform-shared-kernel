> WO-086 (2026-09): historical. Per-package versions are gone (one MinVer version repo-wide); SharedKernel.Application.Behaviors is SharedKernel.Application.Pipeline; consumer tests compose ApplicationBehaviorsBuilder + RequestPipeline<,> (or AddSharedKernelMediatR) instead of AddMediatR; Resilience, fire-and-forget and DualApproval were deleted. Closed 20 accumulated Published-phase tasks (P-07..P-26) in one session, spanning five work orders (WO-036/039/040/041/058) that had each shipped through Docs but never through Published. `SK.05.Published` went 6/23 → 23/23.

**Version-bump decision:** both `SharedKernel.Application` and `SharedKernel.Application.Behaviors` bumped `1.0.0` → `1.1.0` as a SINGLE coordinated minor bump, not five separate bumps. Rationale: every one of the five work orders' own phase notes explicitly states its changes are additive/non-breaking (streaming vocabulary, parallel dispatch, fire-and-forget infra, TracingBehavior, ResilienceBehavior, CacheInvalidationBehavior, idempotency response replay, AddDefaultBehaviors, ILoggableRequest, DualApprovalBehavior — all new types/members, zero signature changes to existing public API). Per SemVer, any number of purely-additive deltas collapse into one minor bump. This mirrors the `01.Core`/`SharedKernel.Primitives` 1.1.0 precedent (P-384/WO-059) cited directly in the phase notes as the analogous case.

**Consumer-verify harness is the substantive deliverable, not the packing.** The pre-existing `ConsumerVerifyTests.cs` in `SharedKernel.Application.Behaviors.Tests` only covered the original WO-035 seven-behavior pipeline (4 tests). Extended it with 11 new tests to prove every canonical pipeline slot added since — Tracing, Resilience, CacheInvalidation, fire-and-forget dispatch, idempotency response replay, AddDefaultBehaviors, ILoggableRequest, and the full DualApproval maker-checker flow — all through a real `ServiceCollection` + `AddMediatR` + `ApplicationBehaviorsBuilder` chain (never hand-rolled `RequestHandlerDelegate<TResponse>` mocks), per this domain's own test-authoring rule. `SharedKernel.Application.Tests/ConsumerVerifyTests.cs` also got one new test for the `AddSharedKernelApplication(configure)` parallel-dispatch overload.

**Real pitfall discovered — NOT obvious from any doc:** NSubstitute (via Castle DynamicProxy) cannot generate a proxy for `ILogger<TRequest>` when `TRequest` is a `private`-nested class inside the test class. It throws `ArgumentException: Can not create proxy for type ILogger'1[...] because type ...+LoggableGetOrderTotalQuery is not accessible`. Fix: any test type used as a generic argument to a substituted interface (e.g. `ILogger<T>`) must be `public`, even if nested. This matches why the pre-existing `LoggingBehaviorLoggableRequestTests.cs` declares its `ILoggableRequest<TResponse>` test types at file scope as `public` rather than as private nested classes — that wasn't an arbitrary style choice, it's load-bearing.
