WO-051 dispatched seven 03.Domain phases (P-307..P-313) in one batch, 2026-07-29. Targets `SharedKernel.Domain` v1.6.0 → v1.7.0. 41 new tasks added across all 6 state-map phases (D-34..D-42, S-07/S-08, C-38..C-46, T-31..T-39, DO-30..DO-36, P-11). All still `○` Pending as of this writing — not yet implemented.

**Key locked decisions** (grounded against actual shipped `.cs` source, not just the phase-input prose — several assumptions in the phase input turned out to need verification):

- **P-307 (composite Include/StringInclude propagation)**: confirmed by reading `AndSpecification.cs`/`OrSpecification.cs`/`NotSpecification.cs` that `AndSpecification<T>` already unions `StringIncludes` correctly but drops expression `Includes`; `Or`/`Not` drop both. Fix is additive `foreach`-append via existing `AddInclude`/`AddStringInclude` builders — no new public members.
- **Discovered documentation gap**: `StringIncludes`/`AddStringInclude` were already shipped on `ISpecification<T>`/`Specification<T>` (confirmed via source read) but were **never documented in 03.Domain/CLAUDE.md** before this pass — likely slipped through an earlier phase's Docs step. Corrected as part of DO-30 rather than filed as a separate defect, per the "note the correction explicitly" instruction.
- **P-308 (KeysetSpecification<T,TKey>)**: designed as a `PagedSpecification<T>`-sibling extending `ReadOnlySpecification<T>`. Mandatory Id tiebreaker via unconditional `ApplyThenBy(idSelector, descending: false)` — never optional, since a keyset boundary is unsound without one. `Skip` fixed at 0; persistence evaluator (06.Persistence, future work) translates `AfterKey`/`AfterId` into `WHERE (SortKey, Id) > (@cursor, @cursorId)`. `AsSplitQuery` flag mirrors `AsNoTracking` propagation exactly (more-permissive-wins).
- **P-309 (IHasAggregateId<TId>)**: deliberately mirrors `IHasTenant`'s exact zero-ceremony one-property-marker shape. Purely opt-in — `IDomainEvent`/`DomainEvent`/`DomainEvent<TPayload>` untouched.
- **P-310 (ValueObject.TryCreate/CheckRule)**: exact parity with the already-shipped `AggregateRoot<TId>.TryCreate<T>`/`CheckRule` (verified exact catch order: `BusinessRuleViolationException` → `Result.Failure(ex.Error)`, then `ValidationException` → `Result.Failure(ex.Errors[0])`). Lives on `ValueObject` so `SingleValueObject<TValue>` inherits both free.
- **P-311 (Guards adoption)**: confirmed via source read that `TenantedAggregateRoot<TId>`/`TenantedAuditableAggregateRoot<TId>`/`TenantedFullAuditableAggregateRoot<TId>` all chain through `: base(id, clock)` to `AggregateRoot<TId>`'s own primary constructor — so **one guard site** (`Guard.Throw.Null(clock, nameof(clock))` in `AggregateRoot<TId>` only) protects all four bases; no per-subclass duplication needed. `Guard.Throw.Null<T>` requires `where T : class`, which cannot apply to unconstrained `StronglyTypedId<TValue>`/`SingleValueObject<TValue>`'s `TValue : notnull` — designed a `TValue`-safe manual null-pattern check instead (no-op for value types). `Entity<TId>.id` stays deliberately unguarded (`default(TId)` is the transient sentinel, not an error) — explicit rule added to CLAUDE.md so a future contributor doesn't "fix" this by mistake. `DomainEventVersionHelper.GetVersion` gets `ConcurrentDictionary<Type,int>` caching (it's called on a per-message infra hot path, unlike the STJ-cached `StronglyTypedIdJsonConverterFactory`). `Entity<TId>`/`ValueObject` gain `IEquatable<T>` — delegates to existing `Equals(object?)`, zero behavior change.
- **P-312 (IPolicy<T>.Explain)**: designed as a **C# default interface member** specifically because the phase's own acceptance criteria demands zero breaking change for existing bare-boolean implementors — a DIM is the only mechanism that satisfies "any existing implementation... continues to compile and behave identically" without a forced override. Composite aggregation mirrors `AndBusinessRule.Message`'s existing `string.Join("; ", ...)` pattern (confirmed via source read).
- **P-313 (Specification<T>.Create ad hoc factory)**: extends the `AllSpecification<T>`/`EmptySpecification<T>` sealed-wrapper precedent via an `internal sealed CriteriaSpecification<T>`. Explicitly does NOT relax the constructor-only/no-fluent-chaining rule for *named* specifications — framed as strictly for one-off/throwaway filters.
