Invoking `Skill(skill: "state-map-phase", args: "...")` does **not** update any file on its own. The tool call returns/injects the full `state-map-phase.md` command instructions as a subsequent turn's content -- mode detection rules, step-by-step file-edit instructions, format contracts -- exactly as if the user had pasted the command's source. The agent that called it is then responsible for actually reading the sub state-map, editing task rows, recalculating Overall Progress, appending changelog lines, checking the promotion condition, and (if it fires) editing the root `state-map.md` too.

**Why this matters**: it is easy to assume a `Skill` call for a well-defined maintenance command (`state-map-phase`, `sync-brain`) is like a subagent dispatch that returns a completed result. It is not -- there is no autonomous execution here. The `args` payload passed in the invocation (e.g. a YAML block listing task IDs and new states) is not consumed by anything automatic; the instructions that come back explicitly re-parse fields like `phase_key`/`task_id`/`state` from "the input" as free text, meaning a single `args` block listing five tasks (`S-29`..`S-33`) at once does not match the command's literal one-`task_id`-at-a-time contract -- the calling agent must decide how to reconcile a multi-task update with the documented single-task Sub-map Mode steps (in practice: apply the same mechanical steps once per task, or -- more efficiently -- perform the equivalent file edits directly since the effect is identical and the command has no state of its own between calls).

**How to apply**: When a phase's implementation closes out multiple tasks in the same state-map-phase key at once (the common case for a Scaffold/Design phase where every task in the table finishes together), it is faster and equally correct to skip the `Skill` roundtrip and perform the documented Sub-map Mode steps directly via `Read`/`Grep`/`Edit` against the sub state-map and (if the phase key's promotion condition is met) the root `state-map.md` -- following the exact section/format rules in `state-map-phase.md` (never rename/reorder sections, always append-only changelogs, wrap state symbols in backticks, root Domain Summary Board always 18 rows, Overall Progress counts always sum correctly). Reserve the `Skill` call for when you want the instructions text itself, not for triggering an action.
