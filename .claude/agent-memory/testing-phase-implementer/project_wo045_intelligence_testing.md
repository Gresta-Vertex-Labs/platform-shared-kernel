**Key notching for `InMemoryVectorCollection<TRecord>`'s test design**: to prove `VectorHit.Score`/`.Rank` directionality differs genuinely per `VectorDistanceMetric` (not just "descending vs ascending" in the abstract), use two vectors where cosine and dot-product DISAGREE on ranking order -- e.g. query `(1,0)`, record Y `(1,0)` (cosine=1, dot=1), record Z `(2,2)` (cosine=0.707, dot=2). Cosine ranks Y first (higher similarity); dot-product ranks Z first (larger magnitude dominates) -- this is the only way to prove the two metrics are NOT interchangeable rather than merely computing correctly in isolation. Colinear-same-direction vector pairs (e.g. `(1,0)` vs `(0.5,0)`) don't work for this since cosine is magnitude-invariant and ties.
