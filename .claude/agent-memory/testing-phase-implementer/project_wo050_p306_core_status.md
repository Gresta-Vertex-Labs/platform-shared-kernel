**Design decisions worth remembering for the Tests-phase pass:**
- `FakeRedisChannelService.PublishAsync` performs *genuine* synchronous in-process fan-out — it's not just a recorder. Backing store is `ConcurrentDictionary<string, ConcurrentBag<Func<string,ValueTask>>>`; `UnsubscribeAsync` does a wholesale `TryRemove` (never mutates the bag in place) to avoid a torn-bag read racing a concurrent publish. Handler exceptions are caught and swallowed (never surfaced to the publisher), mirroring the real `RedisChannelService` contract.
- `FakeRedisHashService`/`FakeTypedHashStore<T>.GetFieldAsync<T>` use a **safe pattern-match cast** (`is T typed`, falls back to `default`) — deliberately copying `FakeCacheService.GetAsync<T>`'s existing convention — rather than an unchecked cast that would throw on an incidental mismatch. Only `IncrementFieldAsync` throws (`InvalidCastException`, on a non-`long` existing value) — that's the one deliberate fake-only "surface a caller bug" guard, implemented via the `ConcurrentDictionary.AddOrUpdate<TArg>(key, addFactory, updateFactory, arg)` overload (avoids a closure allocation; `addFactory`/`updateFactory` are `static`).
- `FakeTypedHashStore<T>` has its **own independent backing store** — never composes `FakeRedisHashService`. This folder's fakes have never shared state with each other and this phase continues that.
- `FakeCacheWarmupStrategy`'s ordering-proof mechanism is a **caller-supplied `ConcurrentQueue<string>`** passed to the constructor (never a static field — this package permits exactly two documented static-mutable-state exceptions, `FakerSeeding.Apply` and `AmbientActivityTestHelper`'s `ActivityListener`, and this isn't a third). `WarmupAsync` order is: increment `CallCount` → invoke `OnWarmup` → enqueue to the shared log **unconditionally** → *then* check `SimulateFailure` and throw. Get this order right in tests — a failing strategy's name still lands in the queue.
- `AddFakeCacheWarmupStrategy()` uses `TryAddEnumerable` (needs `Microsoft.Extensions.DependencyInjection.Extensions`), registering `ServiceDescriptor.Singleton<ICacheWarmupStrategy>(_ => new FakeCacheWarmupStrategy(name, order, executionLog))` — so multiple named strategies compose the way `AddCacheWarmup<TStrategy>()` does in production.
