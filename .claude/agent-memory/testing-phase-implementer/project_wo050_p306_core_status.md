**Design decisions worth remembering:**
- `FakeRedisChannelService.PublishAsync` performs *genuine* synchronous in-process fan-out — it's not just a recorder. Backing store is `ConcurrentDictionary<string, ConcurrentBag<Func<string,ValueTask>>>`; `UnsubscribeAsync` does a wholesale `TryRemove` (never mutates the bag in place) to avoid a torn-bag read racing a concurrent publish. Handler exceptions are caught and swallowed (never surfaced to the publisher), mirroring the real `RedisChannelService` contract.
- `FakeRedisHashService`/`FakeTypedHashStore<T>.GetFieldAsync<T>` use a **safe pattern-match cast** (`is T typed`, falls back to `default`) — deliberately copying `FakeCacheService.GetAsync<T>`'s existing convention. Only `IncrementFieldAsync` throws (`InvalidCastException`, on a non-`long` existing value) via the `ConcurrentDictionary.AddOrUpdate<TArg>` overload.
- `FakeTypedHashStore<T>` has its **own independent backing store** — never composes `FakeRedisHashService`. Proven by a dedicated independence test: seed the same (key, field) pair on both fakes with incompatible values and confirm neither read is affected by the other.
- `FakeCacheWarmupStrategy`'s ordering-proof mechanism is a **caller-supplied `ConcurrentQueue<string>`** passed to the constructor (never static). `WarmupAsync` order is: increment `CallCount` → invoke `OnWarmup` → enqueue to the shared log **unconditionally** → *then* check `SimulateFailure` and throw. A failing strategy's name still lands in the queue.
- **GENUINE BUG FOUND AND FIXED during Tests-phase proving** (see `feedback_tryaddenumerable_factory_pitfall.md` for the generalizable lesson): the originally-shipped `AddFakeCacheWarmupStrategy()` used `services.TryAddEnumerable(ServiceDescriptor.Singleton<ICacheWarmupStrategy>(factory))` — this threw `ArgumentException` ("indistinguishable from other services") on the very FIRST call, confirmed by a failing test, not by inspection. Fixed to plain `services.AddSingleton<ICacheWarmupStrategy>(factory)` (no de-duplication) — this is now the shipped, correct implementation. `16.Testing/CLAUDE.md`'s `AddFakeCacheWarmupStrategy` entry and DI Registration code sample were both corrected in the same Tests-phase pass.
