WO-040 (2026-07-07): user asked to analyze `05.Application` and propose new features to make the shared-kernel package system more developer-friendly. This domain was already extremely mature (five prior work orders — WO-035/036/037/038/039 — ten unary + five streaming pipeline behaviors, a DX onboarding preset, real-assembly governance wiring). Rather than re-litigate what already shipped, read the actual shipped `.cs` files, the domain's own self-flagged forward references/deferred-scope callouts, and cross-checked sibling domains for structurally identical precedents already proven twice. All five resulting phases are grounded in one of: a sibling-domain precedent shipped twice already, a self-documented forward reference sitting unclosed in `05.Application/CLAUDE.md`, or a direct filesystem/grep-verified absence — none speculative.

**Key finding methodology**: grepped `16.Testing/SharedKernel.Testing` for any fake covering `IUnitOfWork`/`IAuthorizationContext`/`IIdempotencyKeyStore` (zero found, despite `InMemoryMessageBus`/`FakeUserContext` precedent existing for sibling domains); grepped `13.ServiceDefaults` for `SharedKernel.Application` telemetry wiring (found `WithMessagingTelemetry()`/`WithCachingTelemetry()` for the two sibling domains but no `WithApplicationTelemetry()` counterpart, even though `05.Application/CLAUDE.md` explicitly documents this as a "future work, out of scope here" forward reference); read `00.Governance/SharedKernel.Analyzers`' existing `SK0014`/`SK0015`/`SK0016` (WO-038 P-235) and found they already mechanize three consumer-facing `05.Application` misuse patterns — meaning the next three undispatched "code review must catch this, the compiler will not" callouts in `05.Application/CLAUDE.md`'s Hard Violations section are a direct continuation of an already-proven governance pattern, not new tooling.

**Five phases, all `Depends on: None` (independently dispatchable):**
- P-244 (`16.Testing`): test doubles for the three `05.Application.Behaviors` local seams (`IUnitOfWork`, `IAuthorizationContext`, `IIdempotencyKeyStore`/`IIdempotencyResponseStore`), mirroring `InMemoryMessageBus`/`FakeUserContext`.
- P-245 (`16.Testing`): promote the `SharedKernel.Application.Behaviors.Tests`-internal-only reusable pipeline test harness (WO-036) into a publicly consumable `16.Testing` capability — currently every downstream service testing its own commands against Authorization/Idempotency/Transaction has zero shared tool and must hand-roll `ServiceCollection`+`AddMediatR`+`ApplicationBehaviorsBuilder` wiring. Framed explicitly against [[feedback_verify_shipped_code_not_docs]]'s own WO-039 finding: a pipeline-level test would have caught the fire-and-forget self-blocking bug immediately, and no consumer had the tool to write one.
- P-246 (`05.Application`): opt-in structured request/response payload logging, closing a gap `LoggingBehavior`'s own doc comment has self-flagged as deferred since WO-035's first pass. Designed as a self-supplied-field marker (mirroring `ICacheableQuery.CacheKey`/`IInvalidatesCache.CacheKeysToInvalidate`'s existing precedent), never reflection — deliberately avoids introducing the platform's first reflection-based property enumeration in a hot pipeline path.
- P-247 (`13.ServiceDefaults`): `WithApplicationTelemetry()` wiring `"SharedKernel.Application"`'s `Meter`/`ActivitySource` into the host's OTel providers, exact twin of `WithMessagingTelemetry()`/`WithCachingTelemetry()`.
- P-248 (`00.Governance`): three new `SK00xx` analyzers (next sequential IDs after `SK0016`) for the three remaining consumer-facing marker-interface misuse patterns `05.Application/CLAUDE.md` documents as unenforced (command implementing `ICacheableQuery<TResponse>`; query implementing `IInvalidatesCache`; `IRetryableRequest` without `IIdempotentRequest`).
