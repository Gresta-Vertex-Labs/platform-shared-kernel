**Verdict: ACCEPT verbatim, no upgrade** — mirrors the [[project_wo044_search_buildout]] precedent, not the [[project_wo045_intelligence_buildout]] one (no open architectural-authority questions were left for arch-lead to ratify; the domain brain had already resolved everything with reasoning on record).

**Key architectural decision ratified:** single-package shape (`SharedKernel.Workflows.Temporal` only — **no** `SharedKernel.Workflows.Abstractions`), the platform's first capability domain of this kind. Reasoning verified sound: durable execution fails both halves of the platform's abstraction-split test — there is no genuinely swappable second provider (MassTransit sagas/Elsa/Dapr Workflow/Hangfire are different execution models, not alternative implementations of one contract), and the thing an abstraction would need to abstract is the workflow source code itself (determinism constraints, replay semantics, `Workflow.Patched` versioning ARE the programming model, not an implementation detail behind an interface). Consistent with root `CLAUDE.md`'s existing layering rule (already correctly scoped to `01.Core`/`04.Contracts`/`05.Application` before this session). One seam intentionally left extractable if triggered later: `IWorkflowDispatcher` (carries no Temporal type) → `SharedKernel.Workflows.Abstractions`, but only if a second durable-execution backend is ever adopted for dispatch only.

**Notable domain-specific inversion ratified without objection:** `SK0001` (mandatory `IClock`, forbidden `DateTimeOffset.UtcNow`) is **inverted inside `[Workflow]` types** — `IClock` is banned there (workflows are replay code; an injected dependency isn't present on replay), `Workflow.UtcNow` is the only correct clock, and `IClock` remains mandatory inside activities (ordinary DI-resolved code). This is the domain's most-likely-to-be-misapplied rule platform-wide and is flagged for a dedicated `00.Governance` analyzer (P-290) rather than left to code review.

**Phases:** P-287 (17.Workflows, single phase — the domain's own 81-task sub-state-map carries the Design→Published granularity, so root tracks it as one phase per the WO-043/044/045-era convention of one root phase per package), P-288 (16.Testing — `InMemoryWorkflowDispatcher`/`InMemoryWorkflowHandle`), P-289 (13.ServiceDefaults — readiness health check + telemetry, no `ProjectReference` to 17.Workflows), P-290 (00.Governance — topology rules + two new analyzers: non-deterministic-API-inside-workflow, raw-`ITemporalClient`-injection).
