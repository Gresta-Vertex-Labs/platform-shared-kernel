Always verify an unconfirmed third-party SDK shape (enum locations, constructor parameter defaults, method overload sets, naming conventions the runtime derives from reflection) against the **real compiled assembly** via a disposable scratch console project, never from documentation, prose in a brain file, or plausible-sounding guesses — even when a phase spec or brain document states an assumed shape with confidence.

**Why:** In this 17.Workflows session, reflecting the real `Temporalio` 1.17.0 assembly surfaced multiple genuine corrections the brain's Design-phase prose had wrong or hedged on (`WorkflowIdReusePolicy`'s namespace, `ActivityOptions`'s actual type, `ApplicationFailureException`'s defaulted parameters) — and, critically, surfaced a load-bearing behavioral finding (the activity-naming-collision on `[Activity]`-attributed inherited methods) that was not something the brain could have specified at Design time at all, because it required empirically running `ActivityDefinition.CreateAll` against two sibling classes to observe. Guessing here would have shipped a `CommandActivity<TCommand>` design that silently collides the moment two command activities are registered in the same worker — invisible until runtime, in production. The task's own phase spec explicitly named this precedent ("the `09.Search` reflect-the-real-SDK precedent, which caught five genuine defects there") and it held again here.

**How to apply:** For any Temporal/SDK-shape question in this domain (or analogous unconfirmed-shape questions in any domain), write a throwaway console project referencing the exact pinned package version, use `System.Reflection` to enumerate the real members/constructors/generic-arg counts, and — where a naming or registration CONVENTION is in question (not just a type shape) — write a tiny empirical repro (e.g. two sibling classes sharing an attributed method) and observe the actual runtime behavior rather than inferring it from the type shape alone. Record every correction back into the domain's `CLAUDE.md` immediately so a later phase/session never re-derives or re-guesses it.
